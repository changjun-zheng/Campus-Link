- **现象**：1280 / 1366 / 1440 / 1920 各档下，`header nav` 的 `clientWidth` **恒为 362**、`scrollWidth` **500** ⇒
  「竞赛交流」被截半、「闲聊灌水」完全在屏外；该容器是 `overflow-x-auto` 且 `[&::-webkit-scrollbar]:hidden`，
  **没有任何"还有更多"的视觉提示**，键盘可 Tab 到但在视口外；
- **根因**：页头内层 `max-w-page = 1080px`，logo 145 + 右侧簇 533 + 间距 40 之后，导航只分到 362（与窗口宽度无关）；
- **一次被回滚的修复**：把导航改 `md:flex-none` 后 `scrollWidth == clientWidth`，但**页头折成两行**
  （导航挤走 logo / 搜索），而首页左右栏 sticky 偏移按 60px 顶栏写死 ⇒ 回滚。**教训：宽度指标通过 ≠ 布局正确，必须看图**；
- **建议**（待发起人定，属全局布局取舍）：① 加宽容器 `max-w-page`；② 右簇（搜索 / 提问 / 登录）在窄档位收缩；

- **处置（CR-114）**：发起人选定「加宽容器」——`--cl-container` 1080 → **1280px**，页头导航余量 362 → **520**，`scrollWidth == clientWidth`、**页头仍单行 60px**；首版取 1240 实测导航只到 480（还差 20px），故定 1280。回归：13 条路由 1440 下横向溢出为 0、375 宽保持原两行设计；after 截图见 `设计/UI规范/screenshots/ui-polish-2026-10-20/1-home.png`。

#### BUG-013：前端把登录响应的过期时间字段名写错，`cl_exp` 从未落盘（✅ 已修复，2026-10-22 [CR-116](变更日志/变更台账.md#cr-116)）

**状态：✅ 已修复。** 缺陷：后端 `AccountController.AuthResponse` 的字段是**单数** `expiresAtEpochSecond`，而前端 `api/auth.ts` 的 `AuthResponse` 接口与 `stores/auth.ts` 读的是**复数** `expiresAtEpochSeconds` ⇒ 登录 / 注册 / 续签后 `expiresAt` 恒为 0、`cl_exp` 从未写入 localStorage。后果：BUG-004 的「启动即清理过期会话」实际从未生效（一直靠后端 401 兜底），且 CR-116 的「剩余 < 2 天续签」也失去触发依据。修复：前端按后端字段名改为 `expiresAtEpochSecond`（三处读取同步）。**验证**：`npm run lint` exit 0、`npm run build` 通过；CDP 实测登录响应字段存在、会话落盘后守卫续签链路正常（`cl_exp` 更新为 7 天后）。**边界**：这是前端单侧字段名修正，**零契约变更**（后端本来就是对的）；旧缓存里 `cl_exp` 为空的用户下次登录即恢复正常。
