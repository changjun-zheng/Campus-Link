**验收边界**：正常浏览器链路使用随机验证码的开发日志通道，本机 SMTP 夹具只验证协议接收，不代表真实邮箱收件。未测试互联网 SMTP 的认证与 TLS 成功握手、投递到真实收件箱、垃圾邮件归类或服务商限额。存码失败的客户端响应由用例测试验证，本轮浏览器故障页面使用真实 SMTP 连接失败验证；不把两者混称为 Redis 故障浏览器实测。完整外部送达须在后续取得配置和授权收件人后补验。

内置浏览器与本机控制工具均因运行目录不存在启动失败，经用户明确授权改用独立 Playwright Chromium 完成浏览器回归。数据库复用此前的隔离 MySQL 3307，Redis 使用独立 DB2；开发模式后端 8089、邮件故障模式 8091、前端 5186／5185，原开发库未连接。保留合成注册账号与自然过期的缓存；长日志位于 `D:/Workspace/cr193-runtime/`，未删除数据或修改 .env／凭据／证书／CI。

## 2. 配置与启用

继续使用既有 Spring Boot 邮件依赖，无新增依赖或数据库迁移。仅在启动进程环境中注入配置，不把凭据填入版本库。

| 变量 | 约定 |
|---|---|
| `CODE_SENDER_MODE` | 开发缺省 log；启用 SMTP 设置 mail；生产 profile 为 mail，守卫禁止切回 log |
| `MAIL_HOST`／`MAIL_PORT` | SMTP 地址／端口，端口 1～65535；STARTTLS 常用 587，隐式 TLS 常用 465，以服务商提供值为准 |
| `MAIL_USER`／`MAIL_PASSWORD` | 认证账号／授权凭据，邮件模式必填；不假设用户名等于发件邮箱 |
| `MAIL_FROM` | 必填纯邮箱地址，须由服务商允许该账号使用；不接受显示名格式或换行 |
| `MAIL_STARTTLS_ENABLED` | 缺省 true；开启时要求升级成功 |
| `MAIL_SSL_ENABLED` | 缺省 false；与 STARTTLS 必须恰好开启一个；隐式 TLS 时设 true、STARTTLS 设 false |
| `CAPTCHA_FIXED_CODE` | 开发原缺省保留；本机随机码验收显式设空；生产必须为空，由既有守卫阻断非空覆盖 |
| `MAIL_HEALTH_ENABLED` | 原缺省 false；如按需开启，健康查询才探测邮件服务，不能把启动成功当成邮箱可达 |

有效 SMTP 配置必须满足：协议 smtp、认证开启、证书主机名校验开启、无 `mail.smtp.ssl.trust` 特例、JavaMail debug 关闭、启动 test-connection 关闭。mail 模式的校验与生产守卫使用同一规则；mode 大小写与条件装配一致，不能用大写 MAIL 绕过检查。非法模式或邮件配置启动即失败，消息只列配置项名，不回显值。

连接／读取／写入超时默认 3000／5000／5000ms；覆盖必须为正值且不高于对应上限。它们是各阶段超时，并非整个 HTTP 请求严格 13 秒截止。没有 SMTP 自动重试，不使用 RabbitMQ 发验证码。

## 3. 接口与失败处理

`POST /api/v1/auth/captcha` 的入参、公开属性和成功外壳不变；新增 `2018 / 503`：“验证码发送失败，请稍后重试”。原 2002／2003 分别表示重发间隔与日额度。

顺序为联系方式／通道校验 → 限流槽位 → 日尝试数 → 一次生成验证码 → 发送 → Redis 保存。邮件模式手机号在额度之前拒绝；开发 log 模式保留手机号链路，短信服务未实现。

- SMTP 抛错：不写新验证码、不覆盖上一条仍有效的码；本次仍占 60 秒重发间隔与日额度，防止反复攻击供应商。
- SMTP 接受、Redis 保存失败：返回 2018，不自动重试发送。收件人可能收到尚不可用的新码，需等待重发；不承诺邮件与 Redis 原子提交。
- 只有发送与保存均成功才响应成功，TTL 从保存时开始。正常邮件有效期文案读取配置；实际送达延迟可能缩短用户剩余可用时间。
- SMTP 接受不等于已进收件箱；认证失败、TLS 失败与超时均不得降级为开发日志或明文 SMTP。

成功日志只记录接受事件及 operationId；失败日志只记录 transport／store 阶段和 operationId。operationId 用于定位单条操作，不冒充客户端响应 traceId。供应商异常不保留在领域异常 cause 中，避免统一日志兜底泄露信封或凭据。开发日志通道仍按已有约定输出合成验收验证码，证据中不保存有效码。

## 4. 真实邮箱补验与维护

用户在本机进程环境提供配置，并明确授权测试收件地址后，执行随机码发送→真实收件→注册／登录，并记录脱敏发件域、接受／收件时间、响应状态及遮盖后的截图；不记录密码、授权码、有效验证码或完整真实邮箱。不要将本机夹具或日志取码记作真实送达。

故障排查先确认错误类别：2002 等待重发；2003 次日或额度策略处理；2018 检查 SMTP 认证／TLS／发件人权限或 Redis 写入。应用启动失败先按列出的配置项修正，不通过关闭 TLS／校验证书／生产守卫排除错误。

回滚本批代码和契约无需迁移或数据回补。生产 SMTP 故障保持失败响应与限流，修复邮件服务后恢复；不启用固定码、日志回退或跳过学籍核验。已发邮件无法撤回，验证码自然过期。
