## 1. 结论

**PRD §4 的三项性能指标全部达标**（本机真实栈口径）：

| 指标 | PRD 要求 | 实测 | 结论 |
|------|---------|------|:--:|
| 普通读接口 P95 | ≤ 500 ms | 最高 **27.96 ms**（列表最新） | ✅ |
| 发布类接口 P95（含机审） | ≤ 800 ms | 发帖 **14.92 ms** / 回帖 **12.86 ms** | ✅ |
| 列表页首屏 P90（生产构建） | ≤ 2 s | 最高 **936 ms**（帖子详情 LCP） | ✅ |

## 2. 环境与口径

- **运行环境**：Windows 开发机；MySQL 8 / Redis 7 本机原生服务；后端 8088（Spring Boot 4.1 / JDK 21）；前端 **生产构建**由 `vite preview` 服务（4173，经 `preview.proxy` 代理 `/api`）；开发库数据。
- **API 压测**：`backend/scripts/perf/run_api_perf.mjs`，零依赖 Node 内置 `fetch`；读接口**每项 200 次、并发 10、预热 20**；写接口**各 20 次、并发 5**；计时为「fetch 开始 → 响应体读完」的端到端耗时；非 2xx/3xx 不计入分位（避免限流响应稀释分布）。
- **首屏**：`backend/scripts/perf/run_lcp.mjs`，隔离无头 Edge + CDP，`Emulation.setDeviceMetricsOverride` 强制 **1440×900 @DPR1**、**缓存禁用**、每次整页导航，等待 load 后再观察 LCP 2.5 秒；每页 **10 次**。
- **写压测数据**：以管理员身份发布 `[perf] P95 基线 …` 帖子 20 条 + 每帖 1 条回复，测后经 `DELETE /posts/{id}` **软删除 20/20**（墓碑行留在开发库，父帖删除后回复不可见）。

## 5. 边界（防止读大）

1. **本机回环**：无公网 RTT / TLS / 带宽约束，数字代表「应用处理 + 本机库 + 前端渲染」的量级，**不是线上 SLA**；线上复测须等 A3-8 部署形态落定后在有代表性的环境重跑。
2. **开发库数据量**：当前帖子量为演示规模，未做 10 万帖 / 1000 楼容量压测；容量指标（PRD §4）本轮**未验证**。
3. **写压测的样本量**：20 条样本的 P95 是「第 19 个值」，仅能说明量级；且写压测在开发库留下 40 条软删墓碑。
4. **首屏口径**：生产构建 + 本机静态服务 + 缓存禁用，测的是 **LCP**（PRD「首屏」的代理指标），不是「用户可交互时间」。

## 7. 移动端复测（2026-10-29，[CR-172](../变更日志/变更台账.md#cr-172)）

**口径**：375×812 @DPR2（touch / mobile）、CPU **4×**、网络 **1.6 Mbps 下行 / 750 kbps 上行 / 150 ms RTT**（Lighthouse 移动端默认档）、**每页冷缓存**（清 HTTP 缓存 + `Network.setCacheDisabled`），整页导航后观察 7 s，**每页 3 次取中位数**。脚本 [`run_mobile_perf.mjs`](../../backend/scripts/perf/run_mobile_perf.mjs)；原始数据：[优化后](性能基线-2026-10-29/mobile-perf.json) · [旧素材对照](性能基线-2026-10-29/mobile-perf-before-assets.json)。

| 页面 | 旧素材 总字节 / LCP / TBT | 优化后 总字节 / LCP / TBT | CLS |
|---|---|---|---|
| `/` | 263 KB / 2416 ms / 450 ms | **209 KB** / 2356 ms / 459 ms | 0 |
| `/post/51` | 275 KB / 3048 ms / 298 ms | **235 KB** / 2988 ms / 292 ms | 0 |
| `/search?q=Java` | 225 KB / 2920 ms / 491 ms | **192 KB** / 2860 ms / 466 ms | 0 |
| `/teams` | 226 KB / 2808 ms / 457 ms | **193 KB** / 2784 ms / 448 ms | 0 |
| `/login` | 220 KB / 2512 ms / 417 ms | **187 KB** / 2536 ms / 403 ms | 0.0425 |

**本轮做了什么**（同路径覆盖，数据库与默认头像映射不变）：
- `wordmark.png` 565×98 / **56 KB** → 345×60 / **24 KB**（实际显示高 20 px，345 px = 3× 密度）；
- 24 张默认头像 256×256 / **172 KB** → 128×128 / **71 KB**（最大显示 64 px，128 = 2× 密度）；
- 视觉核对：1440 页头文字标与 64 px 主页头像清晰，无可见退化。

**结论**：页重量确定性 **−15~20%**（首页 263 → 209 KB）。**LCP / TBT 没有统计意义上的改善**——差异在 ±100 ms 的测量噪声内；瓶颈不是图片，而是**主包 JS（111 KB gzip）在 4× CPU 下的冷启动解析/执行**。

**残差（下一轮候选，未实施）**：
1. 5 页 LCP **2.36~2.99 s**（详情 2.99 s 超 2.5 s 良好线）、TBT **292~466 ms**（>200 ms）——主包 + 懒加载路由 chunk 执行、以及详情页数据请求要等组件挂载；
2. 登录页 CLS **0.0425**（bare 页头高度 92 → 55 px 落定）；
3. 可选方向：举报弹窗 / `ElMessageBox` 等交互型 EP 组件改按需加载、评估替换外壳 EP 布局组件、或 SSG/SSR 预渲染。**这些属代码结构调整，需另开 CR 并单独验证。**

**边界**：单机回环 + preview、无公网 RTT / TLS、单内核；3 次取中位数已压低部分噪声，但仍受宿主机负载影响，**不得当作线上 SLA**。

## 8. 前端主包瘦身（2026-10-30，[CR-174](../变更日志/变更台账.md#cr-174)）

**结论**：生产构建主包 **316.5 KB → 253.4 KB**（gzip **114.0 → 92.3 KB，−19%**）；首页首屏 API 由 **7 次（自动拉完 page 1~4）降到 4 次**；举报弹窗改为异步块，详情页首包不再含弹窗侧组件。

**做法**（按 sourcemap 归因逐个拆）：
1. **用户菜单**：`el-dropdown` → 自绘 `UserMenu.vue`。EP 的 dropdown 会把 popper / tooltip / scrollbar / focus-trap 整链（≈30 KB）带进主包；自绘版保留点击开合、方向键 / Home / End、Esc、点击外部关闭与焦点回还。
2. **头像**：`el-avatar` → 原生 `span + img`。**根因**：EP 的 avatar 引入了 `avatar-group-props → tooltip` 的属性定义，使 popper 常驻首包；原生版保持圆形 / 底色 / 首字规则，并给图片补 `loading="lazy" decoding="async"`。
3. **举报弹窗**：拆为 `ReportDialog.vue` 并用 `defineAsyncComponent` 按需加载（首次点「举报」才请求 chunk）。
4. **首页窄屏触底**：原来列表容器与内容等高，`distance` 恒为 0，首屏自动连续拉 4 页 / 24 条；窄屏改按窗口滚动距离判定，首屏只拉 1 页，滚动到近底再续载。
5. 审计顺带修：匿名详情页提示条内「去登录」链接只靠颜色区分（1.19:1）⇒ 行内链接补下划线。

**验证**：首页 / 详情（匿名）桌面与移动 Lighthouse 均 **100 / 100 / 100**；用户菜单（点击 / 方向键 / Esc / 外点）、头像 128 px 加载、举报框（点击加载 `ReportDialog` chunk、Esc 关闭）真机实测；`build` / `lint` / `typecheck` 通过。

**残差如实**：单次冷缓存实测 LCP **2.47~3.06 s**、TBT **547~708 ms**（波动大），**仍未达到 LCP <2.5 s / TBT <200 ms**；主包仍含 dayjs（≈7 KB）、EP input（≈10 KB）、EP icons（≈12 KB）与 Vue 内核；TBT 主要受主包解析/执行影响，下一步可替换顶栏 `el-input` / `el-button`、核查 dayjs 的桶导入来源，或引入 SSG 预渲染。
