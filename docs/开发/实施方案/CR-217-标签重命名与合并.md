## 1. 目标

CR-132 交付的标签管理只有列表与删除，并明确写下「合并 / 重命名另开 CR 做」。用户自建标签会天然漂移（`Java` / `java 基础` / `JAVA`），运营目前只能删除再让作者重挂，帖子侧会丢标签。本 CR 补**重命名**与**合并**两个动作，约束是：一次事务内同步 `tags` / `post_tags` / `posts.tags` 三处，全部写审计。

## 2. 范围

- **做**：
  - `PUT /api/v1/admin/tags/{id}`：重命名（`name` 1~32 字，去首尾空白；与其它标签重名 → `409 / 3008 TAG_NAME_TAKEN`；标签不存在 → `404 / 3001`），事务内改 `tags.name` 并把受影响帖子的 `posts.tags` 冗余列中的旧名替换为新名。
  - `POST /api/v1/admin/tags/{id}/merge`：合并（body `{targetId}`；源 / 目标须都存在、不得相同），事务内把源标签的 `post_tags` 关联迁到目标（同帖已挂目标则丢弃重复）、重写受影响帖子的冗余列（旧名 → 目标名并去重）、目标 `use_count += 源 use_count`、删源标签行。
  - 两个动作各记一条审计：`TAG_RENAME` / `TAG_MERGE`（目标类型 `tags`，detail 含旧名 / 新名 / 受影响帖子数）。
  - 新增错误码 `3008 TAG_NAME_TAKEN(409)`；管理后台标签页补「重命名」「合并」入口；审计页动作筛选补两个标签。
  - 单测、契约快照、技术方案 §5、台账 / 驾驶舱同步。
- **不做**：
  - 不做批量重命名 / 批量合并、不做标签合并预览（影响面先看再确认）；不做标签排序 / 颜色。
  - 不改 `tags` / `post_tags` 表结构与索引（V1 既有唯一键够用），不新增迁移。
  - 不改用户侧发帖 / 编辑标签的入参规则（仍是 0~5 个、单个 ≤32 字）。
