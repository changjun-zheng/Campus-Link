## 1. 目标

后台处置用户目前只能手填数字 id（CR-209 的封禁 / 警告 / 禁言共用 `banUserId`，内容搜索虽返回 `authorId` 但页面不展示）。新增仅 SUPERADMIN 可用的用户检索：按 **id 精确**或**昵称关键字**查账号，返回基础状态，并可从结果或内容行一键填入处置目标，闭合「发现用户 → 处置」链路。

## 2. 范围

- **做**：
  - 新增 `GET /api/v1/admin/users?keyword=`：仅 SUPERADMIN；`keyword` 为纯数字时先按 id 精确查，再做昵称 LIKE；最多返回 50 条，`truncated` 明示是否还有更多；只返回 `id / nickname / role / status / mutedUntil / createdAt`。
  - 前端「内容处置台」新增 SUPERADMIN 专属「用户检索」区；结果行「设为处置目标」填入 `banUserId`，并滚动到下方操作区；`USER` 且 `ACTIVE` 的行可「填入运营授予」。
  - 内容搜索结果补作者 id 展示与「处置作者」按钮（复用同一填入动作）。
  - 单测、契约快照、技术方案 §5、界面规范 §5.9、台账与驾驶舱同步。
- **不做**：
  - 不做邮箱 / 手机号 / 学号检索或展示——敏感字段等值查询需另定口径，本 CR 只查昵称与 id；
  - 不做分页、用户详情页、批量处置、OPS 开放（仍仅 SUPERADMIN）；
  - 不新增数据库迁移，不改账号写路径，不新增错误码。
