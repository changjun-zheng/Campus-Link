## 1. 目标

堵住个人资料里最后一个**用户可写、公开展示**的自由文本字段：`major`（专业）。它当前只有长度 64 与字符集禁则，既不过机审、也不受 CR-119 的引流 / 联系方式禁则约束——用户可把违禁词或「加微信…」写进专业，绕过昵称 / 签名的两道防线。

## 2. 范围

**做**

- `ProfileApplicationService.updateProfile` 的机审入参由 `(nickname, bio)` 扩为 `(nickname, major, bio)`；
- `UpdateProfileCommand.major` 增加 `FieldRules.CONTACT_BANNED_PATTERN`（与昵称 / 签名同一禁则、同一提示口径）；
- 补单测（专业命中机审 → 5001；禁则覆盖专业）；契约快照再生成并同步文档。

**不做**

- 不改 `school` / `grade`（学校不收集、年级由学号推导，均非用户可写）；
- 不改发帖 / 回帖与昵称 / 签名的既有调用链；
- 不实现真实机审服务商（A3-8 外部决策）。

## 4. 步骤

1. 应用服务扩参 + 命令注解；
2. 单测更新与新增；
3. `SPRING_IT=true mvn -o verify`；
4. 以 `MODERATION_MODE=local` + 词表真机验 `PUT /users/me` 的专业命中 → `422 / 5001`、含引流 → `400 / 1001`、正常 → `200`；
5. 契约重抓 + 台账 / 驾驶舱 / 技术方案同步。

## 5. 验证

- `SPRING_IT=true mvn -o verify` 全绿（基线 521 + 新增用例），SpotBugs 0；
- 单测：专业命中机审 → 5001 且不读库；禁则放行「软件工程」、拦下「加微信 abc」；
- 真机：local 模式专业含违禁词 → `422 / 5001`，专业含「加微信」→ `400 / 1001`，正常专业 → `200`；
- 契约机器比对通过；`git diff openapi.json` 仅 `major.pattern` 移除（预期表达极限）。

## 6. 回滚

- 应用服务入参恢复两参、删除 `major` 的 `@Pattern`、回退两个测试用例；
- 契约快照重抓回 v1.25；无迁移、无新依赖，回滚不影响既有资料数据。

## 7. 实施结果（2026-10-23）

**与原计划一致**：`ProfileApplicationService` 的机审入参扩为 `(nickname, major, bio)`；`UpdateProfileCommand.major` 增加 `CONTACT_BANNED_PATTERN`；无迁移、无新依赖。

**验证证据**

- `SPRING_IT=true mvn -o verify` **524 / 0 failures / 0 errors / Skipped 0** + `BugInstance size is 0`（基线 521 → 524：专业命中机审 1 例 + 命令注解接线 2 例）；
- **真机（log 模式）**：专业填「加微信 abc123」→ `400 / 1001`（引流禁则）；
- **真机（local 模式 + `MODERATION_WORDS=违禁词`）**：专业填「违禁词专业」→ `422 / 5001`；填「软件工程」→ `200`；
- **契约 v1.26**：仅 `UpdateProfileCommand.major` 的 `pattern` 移除（同一字段挂第二条 `@Pattern` 后 springdoc 不再输出，已知表达极限），diff **+1 / −2**、**127497 字节**；规模仍 44 操作 / 39 路径 / 69 schema / 31 受保护。

**偏差如实登记**

- 按发起人连续开发指令**未停等方案确认**（命中"校验注解"门槛），比照 CR-122 先例在方案文末登记；
- `FieldRulesContactPatternTest` **未改动**（计划里曾列）——规则本身已有用例，专业侧的接线改由新建 `AccountCommandsValidationTest` 用 Jakarta Validator 直接证明，比复用规则测试更贴近"注解真的挂上了"这一事实。
