## 1. 目标

默认同步、按配置启用 RabbitMQ；提供最终一致的站内通知。本机低负载下正常消息 5 秒内可见，故障后可补发、重复投递不重复通知。

## 2. 范围

回帖、引用、采纳、帖子／楼层点赞、收藏通知；Outbox、消费凭证、发布确认、重试、死信和重放。保留私信与内容处置通知同步落库、SSE、自触发／拉黑抑制。单体、单节点消息服务，不承诺集群高可用；不改公开接口，不安装升级消息服务，不改凭据文件或 CI。

## 3. 改动点（文件级）

- `backend/pom.xml`：AMQP starter，沿用 Boot BOM。
- `module/notification/{domain,application,infrastructure}`：版本化事件、端口、事务编排、数据库与 RabbitMQ 适配器、调度和监控。
- `db/migration/V11__notification_outbox.sql`：Outbox 与消费凭证两表；不改旧迁移。
- `config`、`application.yml`：默认禁用、配置校验与条件装配；测试与本机重放命令。
- 技术方案、ER 文档、索引、台账及驾驶舱同步；验收证据单独归档。

## 4. 步骤

1. 默认 `rabbitmq.enabled=false`、`delivery=sync`；异步必须显式开启集成；连接信息外部注入，非法组合启动失败，同步模式不连消息服务。
2. `NotificationRequestedV1` 携带 UUID eventId、schemaVersion=1、类型、触发人／接收人／目标 ID、目标类型和 UTC 时间，不携带展示资料。业务与 Outbox 同事务，Outbox 失败使业务回滚。
3. 每秒领最多 10 条，短事务抢占、60 秒租约，事务外持久化发送；direct exchange／队列、routing key `notification.requested.v1`；correlated confirms + returns + mandatory，3 秒确认超时。成功且无退回才记已发送；失败指数退避至最多 60 秒、租约过期重领。
4. 单消费者、prefetch 20；凭证 UUID 主键与通知同事务；重复不写通知，自触发／当前拉黑仍抑制并登记消费。通知用事件发生时间，提交后沿用 SSE，监听成功返回后确认。
5. 消费最多 3 次（间隔 1、2 秒），耗尽以发布确认转存持久死信队列，转存失败原消息重入队；指标覆盖积压／最老事件、发布与消费失败和死信数，60 秒积压／死信限频告警。维护命令按 eventId 重放且保留原 ID，无公网端点。

**实施口径补充（验收发现后、修改前登记）**：异步通知可能在通知页首次读取后才落库；通知页须订阅现有共享未读状态并刷新列表，带请求序号防止乱序覆盖。不建立第二条 SSE 连接，不改变接口或样式。

## 5. 验证

事务回滚／Outbox 失败、重复消费、提交后确认前崩溃；停服务业务成功与恢复补发；确认丢失、路由失败、租约恢复；有限重试／死信转存失败／原 ID 重放；自触发、拉黑、取消互动。两个合成账号真实浏览器覆盖回帖、引用、采纳、点赞收藏、角标／通知跳转／已读及故障补发；归档事件 ID 与数据库行数。`mvn verify`、真实 Flyway 启动、前端三项检查、文档检查、契约重抓零差异、匿名发帖 401；不预设测试总数。

## 6. 回滚

先切 `delivery=sync`、保持集成启用，排空既有 Outbox／主队列／死信后再关闭集成；消息服务不可用时保留积压，恢复后补发。不删表、凭证或消息，不改旧迁移；原 ID 重放去重，回退部署前确认无未完成事件。

## 实施结果

- 按计划完成 V11 两表、条件装配、事务 Outbox、确认发布、幂等消费、有限重试、确认死信、本机原 ID 重放和监控。
- 验收补修：通知页观察已有共享未读状态刷新，增加请求序号防乱序；无新 SSE 连接或契约变化。
- 原 Windows 服务权限不足，复用已安装二进制建立独立用户态验收环境，未改权限、凭据文件或 CI；原开发库未连接。
- 真实停机补发、路由失败恢复、重复投递、过期租约、死信转存失败保留及原 ID 重放通过；两条无效手工探针留在隔离死信队列。
- 双账号六类通知／跳转／已读／取消互动通过；引用可见约 1.9 秒。后端完整门禁 803 例、零失败／零跳过；前端三项检查通过，OpenAPI 同 Host 重抓零差异，匿名发帖 401。
- 精确崩溃窗口使用状态夹具验证，未做集群或生产压力验收；[证据、维护与回滚](../通知异步化验收.md) 为单一详情记录。
