## 1. 目标

把提测准入门仍未满足的一项——**静态扫描**——做掉（[问题清单](../../项目现有问题清单.md) **E-003** / [W-05](../../流程偏离记录.md) 三项硬指标之一）：后端接入 **SpotBugs**、前端接入 **ESLint**，两者都在**本地命令里强制**，后端并因绑在 `verify` 而**随既有 `mvn -B verify` 在 CI 自动生效**。量化口径：`mvn verify` 因静态缺陷变红（反证成立）、`npm run lint` 退出码 0；既有 **366** 单测与 `npm run build` 不受影响。

## 2. 范围

- **做**：
  1. 后端 `spotbugs-maven-plugin`（`check` 绑 `verify`、`failOnError=true`、`effort=Max` / `threshold=Medium`）；
  2. 新增精确排除清单 `backend/spotbugs-exclude.xml`（每条 `<Match>` 注明理由，**不整类跳过**）；
  3. 前端 `eslint`（flat config）+ `eslint-plugin-vue` + `typescript-eslint`，新增 `npm run lint` / `lint:fix`；
  4. `AGENTS.md`「常用命令」补两条命令与一句说明；
  5. 台账 §1 登记、README §2 版本同步。
- **不做**（逐条给理由）：
  - 后端 **Checkstyle / PMD**（风格门，与 SpotBugs 职责不同，另议）；
  - 前端 **Prettier / vue-tsc**（格式化与类型门，非"静态扫描"这一项）；
  - **`findsecbugs` 安全探测器首轮不引**（避免基线一次过大；另议）；
  - **CI workflow 文件改动**——属红线：后端因插件绑 `verify` 而**无需改**；`frontend-ci.yml` 加 `npm run lint` 只出 §5 备料、**待批后另开小 CR 落地**（同 [CR-090](CR-090-覆盖率与集成测试.md) 先例）；
  - **Code Review 归档（E-004）** 与 **核心模块覆盖率 ≥80%（E-002 残余）**——开 CR-103 不覆盖。

## 7. 实施结果（实施后追加，不回改上文）

**实施完成（2026-10-14，发起人批复「开始实施」）。**

- **后端**：`spotbugs-maven-plugin` 4.8.6.6 绑 `verify`（`effort=Max` / `threshold=Medium` / `failOnError=true`）。**基线 61 条 findings 逐条判定**（`spotbugs:spotbugs` 报告 `target/spotbugsXml.xml`）：
  - **57 条 EI_EXPOSE_REP / EI_EXPOSE_REP2** —— ① Spring 构造器注入共享单例 bean（Service / Controller / Redis 适配器 / 配置）；② `@ConfigurationProperties` 绑定类 `AppProperties`（+ 内嵌 `Ai`）；③ 不可变值载体（web VO / application cmd / `domain.gateway.PageResult` / 领域聚合 `Post`）。三类均属已知误报 ⇒ 按类精确排除（每条 `Match` 注明理由）。
  - **3 条 CT_CONSTRUCTOR_THROW** —— `CryptoService` / `JwtService` / `Account` 构造器会抛异常（密钥 / 参数校验）；规则针对"可被子类化的类 + finalizer 攻击"，三者均为 Spring 组件或领域模型、全仓无子类 ⇒ **按设计接受**（标 `final` 会与 Spring CGLIB 代理机制耦合，未采用）。
  - **1 条 RV_RETURN_VALUE_IGNORED_INFERRED** —— `PostApplicationService#acceptReply` 刻意丢弃 `Post.acceptReply` 的返回值（领域不可变迁移返回新对象，落库走定向 UPDATE）⇒ **按设计接受**。
  - **结论：未发现真缺陷**（故本轮**零后端业务代码改动**）。
- **前端**：`eslint.config.js` flat config（`js.configs.recommended` + `tseslint.configs.recommended` + `pluginVue.configs['flat/essential']`）；`npm run lint`（`eslint .`）归零。两处按规则逐条处理：`vue/multi-word-component-names` 关闭（根组件 `App.vue` 按官方脚手架即单词名）；`vue/no-mutating-props` **仅对 `PostListItem.vue` 关闭**（CR-080 既定的"就地点赞回填当前行"设计需改写父级传入的列表项字段）。另按来源（`vite.config.ts` 的 `AutoImport` + `ElementPlusResolver`，产物是 gitignore 的 `auto-imports.d.ts`）把两个自动导入全局 `ElMessage` / `ElMessageBox` 声明为只读，**保留 `no-undef` 以继续抓真实拼写错误**。
- **发现并当轮修复的既有真缺陷（不是误报）**：`frontend/src/views/AdminView.vue` 两处 ——
  - **BUG-009**：工单处置确认弹窗**自 CR-084 起从未写入模板**（只有 4 个 dialog 状态 + `confirmClose()`，无 `<el-dialog>`、仅留一条 `:deep(.el-dialog)` 死样式）⇒ 点「处置并闭环 / 驳回」无任何反应、`confirmClose` 永不被调用。**修复**：补上意图中的确认弹窗（`el-dialog` + 结论 textarea + 取消 / 确认 → `confirmClose`）。**已登记 [问题清单](../../项目现有问题清单.md) BUG-009**。
  - **BUG-010**：处置台 `targetType === 'REPLY'` 分支调用 `moderateReply`，但该函数**未导入** ⇒ 运行时 `ReferenceError`（与 CR-091「详情页 `reactive is not defined` 整页空白」同因：`npm run build` 不跑 `vue-tsc`，编译期静默）。**修复**：补导入（`api/admin.ts:41` 早已导出）。**已登记问题清单 BUG-010**。
- **验证（实测）**：
  - `mvn -B verify`：**Tests run: 366, Failures: 0, Errors: 0, Skipped: 4** + `BugInstance size is 0` + BUILD SUCCESS（jacoco 行覆盖 60% check 同批通过）。
  - `npm run lint`：exit 0；`npm run build`：通过。
  - `openapi.json`：**零 diff**（本轮无 Controller / VO / 校验注解改动）。
  - **反证**：后端注入临时探针类 → `spotbugs:check` 检出 3 条（`RC_REF_COMPARISON` / `RV_RETURN_VALUE_IGNORED` / `URF_UNREAD_FIELD`）+ BUILD FAILURE，删除后归零；前端注入违规文件 → `npm run lint` exit 1，删除后 exit 0。**两处探针均已删除、工作区无残留**。
- **偏差与遗留（如实登记）**：
  1. **未按原计划"先 false 采基线、再翻 true"分两次提交**——`failOnError` 在排除清单写好前先行翻 true，随后以 `spotbugs:check` 单独验证；结果等价（基线经 `spotbugs:spotbugs` 报告采集），但**没有保留 failOnError=false 的产物作为独立凭证**。
  2. **EI_EXPOSE_REP\* 的排除面比"精确"更宽**：③ 类载体含 `Post`（领域聚合）。理由已写入清单，但**取舍须知情**——若将来在这些类里引入真正需要防御性拷贝的可变持有者，本清单会把它一并静默。
  3. **前端 `no-undef` 对 `.ts` 文件不生效**（typescript-eslint recommended 关闭该规则）；BUG-010 是在 `.vue` 里被 `no-undef` 抓到的。故"未定义标识符"这类缺陷在纯 `.ts` 文件中仍主要靠类型检查兜底（本项目 `npm run build` 不跑 `vue-tsc`）。
  4. **CI 步骤未落地**：`frontend-ci.yml` 加 `npm run lint` 属 CI 红线，只出 §5 备料，待批。后端因插件绑 `verify`，CI 已自动生效。
  5. **浏览器走查未做**：BUG-009 补的弹窗只经 `npm run lint` / `npm run build` 与静态核查，**未在浏览器里点击验证**；承接时须补一次管理后台工单处置的浏览器实测。
