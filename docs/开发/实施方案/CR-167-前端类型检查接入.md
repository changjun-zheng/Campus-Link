## 1. 目标

把 `vue-tsc --noEmit` 变成**本地可跑、CI 必跑**的门禁：`vite build` 只转译不检查类型，CR-166 的「`del` 未导入、点删除标签即 ReferenceError」就是构建与 ESLint 都放过、只在运行期才炸的缺陷。首轮基线（临时安装实测）**86 个错误**，其中 **82 个是 `auto-imports.d.ts` 未纳入 tsconfig**（`ElMessage` / `ElMessageBox` 找不到），**4 个是真实类型错误**；接入后要求 `typecheck` **0 error**。

## 2. 范围

- **做**：
  - 新增 devDependency **`vue-tsc`（锁 2.x，与现有 `typescript 5.5.4` 配套）**；不升级 TypeScript；
  - `tsconfig.json` 的 `include` 补 **`auto-imports.d.ts` / `components.d.ts`**（两者是 unplugin 生成物、当前被 `.gitignore` 忽略，故 **CI 顺序为 Build → Typecheck**，build 会先生成它们；本地首次同样先 `npm run build`，文档写明）；
  - `package.json` 增加 `"typecheck": "vue-tsc --noEmit"`；
  - 修掉 4 处真实类型错误：① 前端 `ReplyVo` 接口补 `likeCount: number`（后端一直有该字段，前端类型漏了，页面已在用）；② `HomeView` 的 `myEntries.icon` 显式标 `IconName`（当前推断为 `string`，与 `SvgIcon` 的联合类型不符）；
  - **CI 红线**：`.github/workflows/frontend-ci.yml` 在 Build 之后、Lint 之前/后新增 `Typecheck` 步（**需本次确认**）。
- **不做**：不升级 TypeScript / Vite；不改 AutoImport 策略、不为 82 处 `ElMessage` 手写导入（保留生成物方案）；不加 ESLint 类型感知规则；不改任何运行时行为、接口、样式；不把生成物 d.ts 提交入库。

## 4. 步骤

- [ ] 1. 安装 `vue-tsc`（锁版本），改 tsconfig 与 script；先 `npm run build` 生成 d.ts；
- [ ] 2. `npm run typecheck` 实测：预期 86 → **4**（若仍有 auto-import 遗漏，按错误清单补 include，不逐条手写导入）；
- [ ] 3. 修 4 处类型错误（`ReplyVo.likeCount`、`HomeView` icon 联合）；
- [ ] 4. 反证：临时把 `const n: number = 'x'` 之类的类型错误塞进一个源文件，`typecheck` 必须非 0；复原后转绿；
- [ ] 5. CI 加 Typecheck 步（Build 之后），本地 `lint` / `build` / `typecheck` 三绿；
- [ ] 6. 文档同步（AGENTS 常用命令、台账回置、驾驶舱 / README）。

## 5. 验证

- `npm run typecheck` **0 error**；反证变红后复原复绿。
- `npm run lint` / `build` 不受影响；产物与当前一致（无运行时代码变化）。
- CI：推送后 `frontend-ci` 实跑含 Typecheck 且绿（本机不能替代）。
- 边界：不保证覆盖 `.vue` 模板里所有运行时行为（vue-tsc 只做静态类型），也不替代浏览器验收。

## 6. 回滚

移除 devDependency 与 script、还原 tsconfig / CI 一行、`git revert` 提交；零运行时影响、无数据/迁移。

## 7. 风险

- **vue-tsc 与 TypeScript 版本耦合**：CR-166 轮 `npx vue-tsc` 默认拉到不兼容的 TS 版本直接崩（`ERR_PACKAGE_PATH_NOT_EXPORTED`），因此实施时**锁版本安装并锁 lockfile**，不浮到 latest。
- **生成物依赖**：`auto-imports.d.ts` / `components.d.ts` 被 ignore；CI 必须先 build 再 typecheck，否则会回到 82 个假错。
- **存量类型债**：若修 4 处后又暴露新错（如 EP 模板类型），按「先修真实错误、再收窄」处理，不放宽 `strict`。
