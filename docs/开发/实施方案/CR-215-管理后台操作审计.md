## 1. 目标

`audit_logs` 自上线起只写不读：名册导入、内容处置、用户警告 / 禁言 / 封禁、角色变更、注销匿名化等 25 类动作全部留痕（F-SAFE-003「全部处置留审计日志」），但后台没有任何查询入口，发起人与超管无法核查「谁在何时对谁做了什么」。本 CR 补一个仅 SUPERADMIN 的只读查询页，把既有审计数据变成可检索证据；**零新增写路径、不改动作词表**。

## 2. 范围

- **做**：
  - 新增 `GET /api/v1/admin/audit-logs`（仅 SUPERADMIN）：`action` 精确筛选、`actorId` 筛选、`days` 限 7 / 30 / 90 天，`page` / `size` 分页；按 `created_at DESC, id DESC` 倒序。
  - 出参：`id / actorId / actorNickname / action / targetType / targetId / detail / createdAt`；操作者昵称 `LEFT JOIN users` 展示，缺失时 `actorId=null → 系统`、其余 → `已注销用户`。
  - V14 纯索引迁移：`idx_audit_created (created_at)`、`idx_audit_action (action, created_at)`——审计表只增不减，默认倒序与动作筛选都需要索引。
  - 管理后台新增仅 SUPERADMIN 可见的「操作审计」页签：动作（可搜索 / 可手输）、操作者 id、时间范围筛选 + 表格 + 分页。
  - 单测、契约快照重抓、技术方案 §5、台账 / 驾驶舱 / 文档索引同步。
- **不做**：
  - 不新增审计写入口、不引入 `@Audit` 切面；不改既有 25 个动作名与 `detail` 口径。
  - 不做导出、删除、保留期清理、按目标 id 检索；OPS 不可见（审计含跨用户处置记录，按「权限管理」归 SUPERADMIN）。
  - 不改表结构列（仅加索引），不新增错误码。
