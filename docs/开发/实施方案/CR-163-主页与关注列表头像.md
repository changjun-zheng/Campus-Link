## 1. 目标

把 CR-162 的默认头像接到**他人主页**（`/u/:id`，64px）与**粉丝 / 关注列表**（40px）：两个页面当前仍用昵称首字占位。完成后，后端 `UserProfileVo` / `FollowUserVo` 各带可空 `avatarUrl`，前端 `UserAvatar` 的 `src` 优先逻辑（已有）自然生效；空值 / 查不到仍回落昵称首字。

## 2. 范围

- **做**：
  - `UserProfileApplicationService.PublicProfile` 增加 `avatarUrl`（取 `account.getAvatarUrl()`），`account/web/UserProfileVo` 同步并透传；
  - `FollowApplicationService.FollowUsers.FollowUser` 增加 `avatarUrl`（同一次 `findByIds` 的 `Account` 已含该列，**不新增查询**），`account/web/vo/FollowUsersVo.FollowUserVo` 同步；
  - 前端 `src/api/user.ts` / `src/api/follow.ts` 接口加 `avatarUrl: string | null`；`ProfileView.vue`（`:src`，64px）与 `FollowListView.vue`（`:src`，40px）传给既有 `UserAvatar`；
  - 契约：`UserProfileVo` / `FollowUserVo` 两个 schema 各 +1 可空属性，重抓快照（零新增端点 / 路径 / tag），同步技术方案 §5 与契约 README；
  - 测试：`UserProfileApplicationServiceTest` / `FollowApplicationServiceTest` 断言头像随资料返回；VO 映射覆盖；契约 T1 / T2。
- **不做**：不动通知 / 后台搜索的头像（另议）；不做上传 / 自选 / 裁剪；不动 `tokens.css`、不加依赖、不改数据库；不为已注销账号特殊造头像（现状匿名化会清空 `avatar_url`，前端回落首字）。

## 7. 风险

- **契约属性新增**：只加可空字段，旧客户端忽略未知字段，向后兼容；仍按既有流程重抓快照。
- **头像尺寸**：源图 256×256、244KB，64px / 40px 渲染由浏览器缩放；页面最多一页 20 条 × ~10KB，量级可接受。
- **已注销 / 匿名化账号**：`avatar_url` 被清空 → 前端自然回落首字，不额外分支。
