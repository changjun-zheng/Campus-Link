## 1. 目标

补齐运营后台 P1「数据看板」（F-ADMIN-005）：给 SUPERADMIN 一个**只读聚合端点 + 页面**，展示用户 / 帖子 / 楼层 / 举报的关键计数，使日常运营不必直接查库。

## 2. 范围

- **做**：
  - 受保护端点 `GET /api/v1/admin/dashboard`（仅 SUPERADMIN），一次返回四组计数：
    - `users`：`total` / `active` / `banned` / `deactivated`（`users.status` 分组，注销账号计入 total 并单列）；
    - `posts`：`total`（`is_deleted=0`）/ `published` / `removed` / `todayCreated`；
    - `replies`：同帖子侧四项；
    - `reports`：`total` / `pending` / `closed`。
  - 口径：作者自删（`is_deleted=1`）不计入内容统计；平台下架计入 `total` 并单列 `removed`；「今日」按 **UTC 自然日** 为界（库内时间为 UTC，前端文案写明「今日（UTC）」）。
  - 后端：account 侧新增 `accountStats()`（跨上下文经 application，符合 ADR-012）；forum 侧新增 `AdminStatsGateway`（domain 端口）→ `AdminStatsGatewayImpl` + `AdminStatsMapper`（3 条 `@Select` 聚合）→ `AdminStatsApplicationService` → `AdminDashboardController` + `AdminDashboardVo`。
  - 前端：`api/admin.ts` 类型与调用；`AdminView.vue` 新增第三个 Tab「数据看板」（**进入 Tab 才加载**，卡片 + 骨架 + 错误重试，沿用现有 Tab 样式）。
  - 契约快照重抓（预期 +1 操作 / +1 路径 / +3 schema），契约 README / 技术方案 §5 / 界面规范 / 台账 / 驾驶舱回置。
- **不做**：
  - 时间序列 / 趋势图 / 图表库（只给当前快照数字，零新依赖）；
  - 按版块 / 按作者的细分排行；
  - 实时刷新 / 定时推送 / 看板数据落表缓存；
  - DAU、停留时长等现有表无法直接得出的指标；
  - 标签管理（F-ADMIN-004）与人工巡查队列（F-SAFE-004）——另开 CR。

## 5. 验证

- **单测**：基线 **567**（`SPRING_IT=true` 0 SKIPPED）→ 预计 **+5~7**；含「匿名 → 401」与「非 SUPERADMIN → 403」两条（AGENTS 约定）。
- **真机**（真实后端 + 真实库）：
  - admin 登录 → `GET /admin/dashboard` 返回 200，四组数字与 SQL 直接计数逐项一致（用户 / 帖子 / 楼层 / 举报）；
  - 普通账号（dev-stu-01）→ `403 / 4002`；匿名 → `401 / 4001`；
  - 今日计数口径：造一条当日帖前后 `todayCreated` 差 1（测后清理）。
- **真实浏览器**：管理后台 → 切「数据看板」Tab → 卡片渲染数字、零控制台错误；匿名访问 `/admin` 仍跳登录。
- **契约**：预期 +1 操作 / +1 路径 / +3 schema（`AdminDashboardVo` + 两个包装 schema），`git diff` 非空但为纯新增。
- **回归面**：既有 4 个 admin 端点（举报 / 处置 / 封禁 / 名册）行为不变；`GET /users/me` 等不受影响。

## 8. 实施结果（实施后追加，不回改上文）

- **与计划一致**：`GET /api/v1/admin/dashboard`（`requireRole(SUPERADMIN)`）、account `countByStatus()` / `accountStats()`、forum `AdminStatsGateway` + 3 条 `@Select` + `AdminStatsApplicationService` + `AdminDashboardController` / `AdminDashboardVo`、前端 `api/admin.ts` + `AdminView` 第三 Tab，均按 §3 落地；§7 四条口径按默认值执行。
- **偏差 1（schema 数量）**：§5 预估 +3 schema，实际 **+2**（`AdminDashboardVo` + `ApiResponseAdminDashboardVo`）——VO 采用**扁平 15 字段**而非嵌套三组，理由：嵌套 record 会让 springdoc 多生成三个顶层 schema（简单名有撞名风险），而该 VO 只服务一张页面。
- **偏差 2（静态扫描）**：本轮 VO 全为 `long` 基本类型、无集合字段，未触发 SpotBugs `EI_EXPOSE_REP`，无需扩排除清单（与 CR-130 不同）。
- **验证实测**：`SPRING_IT=true mvn -o verify` **567 → 574**（0 failures / Skipped 0）+ SpotBugs 0（新增 7 例 / 3 个测试类）；`npm run lint` exit 0、`npm run build` 通过；契约 **v1.31**（46 路径 / 53 操作 / 82 schema / 15 tag / 40 受保护、155900 字节、+143 / −0 纯新增）。
- **真机取证（真实后端 + 真实库）**：admin `200`，四组数字与 SQL 逐项一致（用户 54/53/0/1、帖子 26/24/2/0、楼层 36/36/0/0、举报 1/0/1）；普通用户 `403 / 4002`、匿名 `401 / 4001`；今日计数造帖 **postTotal 26 → 27、postTodayCreated 0 → 1**，作者删除后回 **26 / 0**（`is_deleted=0` 口径生效）；造出的验证帖已由作者删除，无残留数据。
- **真实浏览器验收**：5 步全 PASS（管理员登录 → `/admin` 三 Tab → 点「数据看板」出现四张卡片且数字与基线一致、说明行正确 → Tab 往返数字保持 → 控制台仅 SSE 的 `ERR_ABORTED`）。
- **遗留**：趋势图 / 细分排行 / 实时刷新不在本轮（方案 §2 已列）；`admin-dashboard` 是快照第 15 个 tag。
