## 1. 目标

完善既有通用 SMTP 链路，以随机验证码完成邮件注册／登录；失败、超时、生产漏配行为明确。代码／本机验收与真实送达分开记录；用户已选择本轮先完成代码与本机验收，真实送达未测。

## 2. 范围

做：显式发件人、配置有效期、有限超时、隐私日志、失败处理、生产校验与浏览器回归。保留开发日志／固定码、生产随机码／学籍核验、现有有效期／60 秒重发／每日 10 次。不做短信、通知订阅、RabbitMQ 发验证码、新表、采购、生产部署；不改 .env、凭据文件、证书或 CI。

## 3. 改动点（文件级）

- `CaptchaService.java`、`MailCodeSender.java`：通道前置检查，先发送后存码，邮件内容与异常处理。
- 账号 domain/gateway：发送失败异常；`config` 与 `application.yml`：MAIL_FROM、TLS、3／5／5 秒超时、装配前校验及生产守卫。
- `ResultCode.java`、`AccountController.java`、OpenAPI 快照：2018／503 声明；补测试与验收，技术方案、索引、台账、驾驶舱同步。

## 4. 步骤

1. 复用已有邮件依赖，连接变量 MAIL_HOST／MAIL_PORT／MAIL_USER／MAIL_PASSWORD，新增 MAIL_FROM；不默认把认证用户名当发件人。MAIL_STARTTLS_ENABLED=true、MAIL_SSL_ENABLED=false，mail 模式恰好开一种，STARTTLS 要求升级成功，验证证书身份、不设通配信任；连接／读／写超时 3／5／5 秒，不自动重试。缺失或非法启动失败且只报配置项名；启动校验不联网。
2. 主题沿用“Campus-Link 验证码”，有效期取现有配置。生产日志不含验证码、完整邮箱、凭据或 SMTP 异常原文；失败只记分类与关联信息。开发日志发码保留。
3. 解析联系方式 → 检查通道 → 重发槽位 → 日尝试计数 → 生成 → SMTP 发送 → Redis 保存，均成功才响应成功。SMTP 失败不覆盖旧码；失败仍占间隔与额度。发送成功但存码失败返回失败、不得自动补发；不承诺 SMTP／Redis 原子提交，TTL 从保存开始。
4. 保持 captcha 路径、入参、成功外壳；新增 CAPTCHA_SEND_FAILED(2018,503,“验证码发送失败，请稍后重试”)。发送／存码失败由全局异常处理输出。mail 模式手机号占额度前同错返回，不交 SMTP；不改手机号输入契约，2001／2002／2003 不变。
5. 同步设计与快照、维护说明。真实送达仅在用户指定测试收件人且本机注入连接配置后进行；凭据不进入聊天、源码或证据。

## 5. 验证

单测覆盖邮件 From／有效期、失败旧码保留／不存新码、保存失败 503、限流保留、手机号不发送、漏配／TLS 冲突／生产固定码阻断及日志脱敏。真实启动、随机验证码注册／登录、过期／复用／限流，连接拒绝／认证失败／超时／Redis 保存失败与恢复；浏览器反馈保留输入。完整 mvn verify、前端三项检查、文档一致性、OpenAPI 仅预期变化、匿名发帖 401；证据脱敏、不预设测试数，真实送达缺外部配置标未测。

## 6. 回滚

回退本批代码与对应快照，无数据库迁移或回补。生产故障保留失败提示与限流，修复 SMTP 后恢复，不得回退日志／固定码／跳过核验；开发可沿用日志模式。已发送邮件不可撤回，验证码自然过期。

## 实施结果

- 完成邮件配置守卫（生产复用）、显式 From、有效期文案、有限超时、发送异常隔离与隐私日志；先发送后存码，失败／手机号通道统一 2018／503。
- 本机 SMTP 夹具覆盖接收、认证失败、读取超时与拒绝明文降级；生产进程真实验证漏配／TLS 冲突早失败、配置完整但 SMTP 不可达仍可启动。
- 用户明确选择先完成代码／本机验收，未配置外部 SMTP 和收件人，真实邮箱送达未测；正常浏览器链路使用随机码的开发日志通道，不能算真实收件。
- 内置浏览器与本机工具故障，经用户授权使用独立 Playwright；随机码注册／登录、错误码／复用、倒计时及 SMTP 503 提示／输入保留通过；期限／日额度另用隔离缓存夹具核对。
- 完整后端检查 817 例、零失败／零跳过；前端三项通过，快照相对本轮基线仅新增验证码 503；匿名发帖 401。没有新增依赖／迁移／生产部署。
- 证据、配置与未测边界集中于[邮件验证码验收与维护](../邮件验证码验收与维护.md)；未修改凭据、证书或 CI，未提交／推送。
