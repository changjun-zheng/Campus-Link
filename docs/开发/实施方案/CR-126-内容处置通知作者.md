## 1. 目标

补上 PRD F-SAFE-003 验收句里明确欠着的第三句：**内容被平台下架 / 恢复后，作者收到站内通知**。CR-066 当时把它列为"明确不做"（需新增通知类型 + 前端文案链），本轮补全。

## 2. 范围

**做**

- `NotificationType` 新增 `CONTENT_REMOVED("content_removed")` / `CONTENT_RESTORED("content_restored")`（`notifications.type` 是自由字符串列，**零迁移**）；
- `NotificationApplicationService` 新增 `contentRemoved` / `contentRestored` 两个入口（actor = 处置管理员，recipient = 内容作者，target = 帖子 / 楼层）；
- `ContentModerationApplicationService.moderatePost / moderateReply` 在**状态真的迁移后**调用；幂等重复处置、并发失败出口均不发通知；楼层侧用 `findByIds` 取作者（该读刻意不过滤 status，只排墓碑）；
- 前端通知中心：两个新类型的动作文案与"平台"主体显示；`NotificationType` 联合类型扩展；
- 单测 + 真机验证。

**不做**

- 不改处置端点 / 契约（`NotificationVo.type` 是普通 string，新取值不改变 schema）；
- 不通知被处置内容的点赞者 / 收藏者；不发站外通知；不改审计口径。

## 4. 步骤

1. 后端枚举 / 应用服务 / 处置服务接线；
2. 两个测试类补用例并跑定向测试；
3. 前端类型与文案，lint / build；
4. `SPRING_IT=true mvn -o verify`；
5. 真机：作者发帖 → 管理员下架 → 作者通知出现 `content_removed` → 恢复 → `content_restored`（验证帖删除）；
6. 台账 / 问题清单 / 技术方案 / 驾驶舱同步。

## 5. 验证

- `SPRING_IT=true mvn -o verify` 全绿（基线 526 + 新增用例），SpotBugs 0；
- 单测：状态迁移后通知一次；幂等 / 失败出口零通知；两个新类型的 type / target / recipient 正确；
- 真机：下架与恢复各产生一条作者通知，`actorNickname` 为管理员、文案为"平台 下架 / 恢复了你的帖子"；
- 契约：`openapi.json` 零 diff（`type` 是 string，新增取值不进 schema）。

## 6. 回滚

- 删除两个枚举值与两个应用服务入口、回退处置服务的注入与调用、回退前端文案；
- 无迁移、无新依赖；已产生的通知行保留（只读展示，回滚代码后 `fromCode` 会因未知类型抛错——因此回滚前须一并清理这两类通知行，或保留枚举值只回退发送点）。

## 7. 实施结果（2026-10-23）

**与原计划一致**：两个通知类型、处置服务接线、前端文案与真机验证均落地；无迁移、无契约变更（`NotificationVo.type` 是普通 string，`openapi.json` 零 diff）。

**一处架构修正（G4 实测拦截）**：初版让 forum 侧直接传 `NotificationTargetType`，`ArchitectureGuardTest` 报「forum application → notification domain.model」跨上下文违规；按"跨上下文只调 application"改为通知应用层提供四个显式入口
`contentRemovedPost / contentRemovedReply / contentRestoredPost / contentRestoredReply`，forum 侧不再引用通知 domain 类型。

**验证证据**

- `SPRING_IT=true mvn -o verify` **528 / 0 failures / 0 errors / Skipped 0** + `BugInstance size is 0`（基线 526 → 528：通知应用 +2 例，处置应用原有 9 例补断言）；
- **真机**（dev-stu-15 发帖、admin 处置）：下架后作者通知 `type=content_removed`、`actorNickname=管理员`、`postTitle=内容已删除`、`postId` 不下发（下架内容无落点）；恢复后新增 `type=content_restored`、`postId=57`、原标题可点；验证帖已删除；
- 幂等重复处置、并发失败、目标不存在三类出口均不产生通知（单测断言）。

- 首次 `mvn verify` 报 `Unresolved compilation problems`，根因是上一轮增量编译残留（旧 class 仍引用已删除的 `NotificationTargetType`），`mvn clean compile` 后恢复——与源码无关；
- 真机首次尝试被验证码 60 秒重发间隔挡住（`2002`），等待后用新账号重做；属于开发联调限流，不是产品缺陷；其间产生的一篇孤儿开发帖（id 56）未清理，属本地开发库数据。
