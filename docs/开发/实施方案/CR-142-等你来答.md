## 1. 目标

兑现 [CR-075](../需求/产品优化与新增业务需求建议.md) §2 **N1（★ 最值得先做）**：产品定位第一句是「问有所答」，冷启动期最缺的不是浏览（热榜已覆盖）而是**回答**——用现成的 `posts.type` / `posts.is_accepted` 列做「待解答」筛选，加首页「等你来答」入口，把「提问 → 回答 → 采纳」核心循环真正转起来。

现状取证（2026-10-25）：全仓 `等你来答 / 待解答 / unanswered` **零命中**；公开列表 `GET /api/v1/posts` 现仅支持 `boardCode / sort / page / size`，无任何内容筛选；首页右栏已有「全站热榜」「最新发布」两卡、版块页（`BoardView`）无筛选控件；拉黑（CR-129）/ 举报人排除（CR-140）已内建于列表查询链路，新筛选叠加其上自动继承。附带澄清一处文档漂移：CR-075 依赖链里的「相似推荐纯检索版」实际已由 CR-077 交付（`GET /posts/similar`），不属本 CR 范围。

## 2. 范围

**做**：

- 既有公开端点 `GET /api/v1/posts` 新增可选参数 `filter`，值域仅 `unanswered`（缺省不筛选；**非法值 / 空串 `400 / 1001`，不静默归一**——与同端点 `sort` 的口径一致）；
- `filter=unanswered` 生效时列表 SQL 追加 `type = 'QUESTION' AND is_accepted = 0`（「待解答」= 问答帖且尚无采纳答案；**有回答未采纳也算待解答**）；与 `boardCode / sort / page / size` 正交组合；可见性 / 拉黑 / 举报排除沿用既有链路，零改动自动继承；
- 前端首页右栏新增「等你来答」卡片（Top5，样式复用热榜卡：序号 + 标题 + 回答数；点击条目进帖子详情，「更多」进 qna 版块待解答视图）；
- qna 版块页新增「全部 / 待解答」筛选切换（据 `BoardVo.type === 'QUESTION'` 显隐，非问答版块不露此控件）；
- 契约快照再生成（仅 +1 query param，操作 / 路径 / schema 规模不变）。

**不做**：

- 不建新端点（复用列表链路，避免与搜索 / 列表能力重复）；
- 零迁移（`posts.type` 与 `is_accepted` 均为 V1 现成列）；
- 不做悬赏 / 紧急标识、采纳率统计、「零回答」与「有回答未采纳」细分筛选、待解答消息提醒 / 推送；
- 首页中栏排序 tab **不加第四档**（保持 latest / hot / following 三档，「等你来答」从右栏卡片与版块页进入）；
- 不改 `PostSummaryVo` 出参（`accepted / replyCount` 已含，卡片直接用）。

- **真机**：造三帖对照（已采纳提问帖 / 未采纳提问帖 / 普通讨论帖）→ `filter=unanswered` total 恰为未采纳提问帖数且含 B 不含 A/C；`filter=unanswered&boardCode=qna` 同；采纳 B 后 B 移出；`filter=xyz → 400 / 1001`；抽验拉黑排除仍生效（既有口径回归）；

## 8. 实施结果（2026-10-26）

**原计划 vs 实际**：按 §2 / §3 / §7 默认口径落地，零迁移、零新 schema。**一项计划外发现并当轮修复的真缺陷**：真机取证时发现 `PublishPostCommand.anonymous` 自 CR-139 起声明为原始 `boolean`，Jackson 3（Boot 4 / tools.jackson）对**缺失的原始类型字段**抛 `Cannot map null into type boolean` ⇒ 任何按契约（`anonymous` 非 required、可不传）发帖的调用方一律 `400 / 1001`——前端恰好总是显式传该字段，浏览器链路从未暴露。修复＝`boolean → Boolean` + 消费点 `Boolean.TRUE.equals(command.anonymous())`（缺省 null 即非匿名，与契约一致），补 2 例回归（缺字段反序列化、null 落库非匿名）；**契约零影响**（修复前后快照逐字节同规模，`anonymous` 本就不在 required、type 仍为 boolean）。

**实际改动**：

- 后端：新增 `forum/domain/model/PostListFilter`（`NONE / UNANSWERED`，`fromCode` 先例同 `PostSortOrder`，null → NONE、非法值不归一）；`PostRepository.findPage` 端口、`PostRepositoryImpl`（`UNANSWERED` 分支 `eq(type,'QUESTION') + eq(isAccepted,false)`，SQL 侧过滤、total 同源）、`ForumQueryApplicationService.listPosts`（白名单校验）、`PostController.list`（`filter` 参数 + summary 改写）。
- 缺陷修复：`PublishPostCommand.anonymous` 包装类型化 + `PostApplicationService` 消费点判定。
- 前端：`api/forum.ts` 加 `PostFilter` 类型与透传；`HomeView.vue` 右栏「等你来答」Top5 卡片（标题 + 回答数、`0 回答`主色高亮、「更多」→ `/board/qna?filter=unanswered`）；`BoardView.vue` QUESTION 版块「全部 / 待解答」`el-radio-group`（状态同步进 `query.filter`，支持外链直达；切换重置 page；待解答空态文案区分）。
- 测试：`ForumQueryApplicationServiceTest` +1（unanswered 透传 / 缺省 NONE / 非法值 1001）、`PostRepositoryImplTest` +1（WHERE 含 type 与 is_accepted、NONE 不含）、`ForumPublicReadTest` 并入 filter 匿名用例、`PostApplicationServiceTest` +2（anonymous 缺字段回归）。

**验证**：

- `SPRING_IT=true mvn -o verify` **733 / 0 failures / Skipped 0** + SpotBugs 0 + 覆盖率门禁过（基线 729 → 733，+4 例）；`npm run lint` exit 0、`npm run build` 通过；
- **首轮 verify 唯一失败正是 `OpenApiSnapshotEqualityTest`**（`$.paths./api/v1/posts.get.summary` 代码 vs 归档不一致）——快照探针按设计拦截"改 Controller 忘重抓"，重抓后复跑全绿；
- **真机**（8088 + 双开发账号）：造三帖对照（qna 待采纳 A / qna 未采纳 B / chat 讨论 C）→ `filter=unanswered` 含 A、B 不含 C；`+boardCode=qna` 同、`+boardCode=chat` **total=0**；`+sort=hot` 组合 200；`filter=solved` / 空串均 `400 / 1001`；无 filter 三帖全在；B 回复 + A 采纳后 A 移出（16 → 15）、B 留存；匿名视角可用；**不带 anonymous 字段发帖 200**（缺陷修复实证）；三帖测后清理（unanswered 14 / 全量 24 回到基数）；
- **浏览器（IAB）**：首页右栏「等你来答」Top5 与后端一致（含「N 回答」、`0 回答` 高亮）；「更多」落 `/board/qna?filter=unanswered` 且「待解答」radio 选中、列表 14 条与后端一致；切「全部」URL 去 filter 参数、列表恢复全量；chat 版块 radio 数 0（非问答版块不露控件）；
- **契约**：v1.40（70 操作 / 60 路径 / 122 schema / 20 tag / 55 受保护不变，diff **+9 / −1**＝`filter` 参数块 + summary 改写，219964 字节）。
