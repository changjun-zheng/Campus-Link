## 2. 范围

### 做（五批，**逐批停下验收**）

1. **代码高亮（P0 欠账）**：引入 `highlight.js`（BSD-3-Clause），按需注册约 20 种语言；详情页与楼层两处 `v-html` 渲染后对 `pre code` 着色；github 主题色板**抄成新令牌**而非直接引入其 CSS。
2. **头像体系（仅前端侧）**：新增 `UserAvatar.vue`——有 `avatarUrl` 用之，否则按昵称稳定哈希从 **8 个 pastel 底色令牌**中取一个、文字用**昵称真实首字**、字色按底色亮度自动选深/浅以保 ≥4.5:1；接入顶栏 / 列表项 / 详情页；**顺带移除 `App.vue` 的头像内联样式**（改走新增 `--el-avatar-*` 令牌）。
   > **口径变更（2026-09-15，发起人选定）**：原设想是"本地 8 个占位 SVG 入仓、按哈希取其一"。核实素材后推翻——`04-头像占位/` 的 8 个 SVG 是 **DiceBear「Initials」风格、CC0 1.0**（**许可无问题，原 ⚠️ 解除**），但自带**白字 + 浅色底**，实测对比度仅 **1.27~2.03:1**（连大字 3:1 门槛都不到，首字母实际不可读），且字母由 DiceBear 按种子生成、**与用户名无关**（`zhangsan.svg` 显示 "DF"、`lisi.svg` 显示 "CC"）。故改为**只取其 8 个底色抄成 `--cl-avatar-*` 令牌、头像本体由代码派生**：不入仓任何 SVG 文件、首字母与本人一致、颜色全走令牌。
3. **图标统一为 Tabler**（MIT）：本地 SVG 入仓 + `SvgIcon.vue`（`import.meta.glob` 内联，**零新构建依赖**），替换 17 个自有调用点与 `constants/boards.ts` 的 6 个版块图标。
   > **口径变更（2026-09-15，实施中收窄）**：原设想"40 个本地 SVG 全量入仓"。两点实测推翻——① `import.meta.glob(..., { eager: true })` 是**编译期内联**，未被任何调用点引用的图标会白进首屏包（43 个全量实测 16092 B，实际只用得到 18 个、6446 B），故**只入仓实际引用的 18 个**，素材目录仍保留全量供后续取用；② 本地素材**缺 3 个必需图标**（发布页工具条的 `list` / `photo`、最佳答案标识的 `circle-check`），已按发起人"可拉取 GitHub 开源素材"的授权从 Tabler 上游仓库拉取，**MIT 许可证全文一并入仓**（`src/assets/icons/LICENSE`——本项目对素材做了归一化改写，MIT 要求保留版权与许可声明）。
   > **另一处实测发现**：图标容器**不能复用 `el-icon`**——EP 的 `.el-icon` 带 `fill: currentColor`，CSS 优先级高于 SVG 自身的 `fill="none"` presentation attribute，会把 Tabler 描边图标**灌成实心块**。故 `SvgIcon.vue` 自带 `.cl-icon` 容器。
4. **中文字体子集化自托管**：用**中文网字计划 `cn-fontsource`** 的 woff2 分片包（思源黑体 SC，SIL OFL 1.1），`unicode-range` 按需加载，只取 Regular(400) + Medium(500) 两档。**实施前须先核实两件事**（不过则砍掉本批）：① npm 包内**是否含 woff2 实体文件**（若 `@font-face` 指向其 CDN 则不满足自托管）；② 分片包许可证是否允许再分发。
   > **口径变更（2026-09-15，实施前核实后换包）**：原定的两道门**两个候选包都过了**——`cn-fontsource-source-han-sans-sc-vf@1.0.10` 与 `@fontsource-variable/noto-sans-sc@5.3.0` 均含 **woff2 实体文件 + 相对 `url()`**（CSS 内 `grep https?://` 零命中，不指向任何 CDN）、均为 **SIL OFL 1.1**（允许再分发与网页嵌入，须随附许可声明）。但逐项实测后 cn-fontsource 有四处硬伤，故**改用 `@fontsource-variable/noto-sans-sc`**：
   >
   > | 核实项 | cn-fontsource-source-han-sans-sc-vf@1.0.10 | @fontsource-variable/noto-sans-sc@5.3.0 |
   > |---|---|---|
   > | `font-weight` 声明 | **0 处**——缺该描述符即只有 400 一档，全站 `font-medium`(500) 无匹配字面，会退化成浏览器伪粗 | `100 900` 可变轴，**400 / 500 都是真字形** |
   > | 覆盖本项目 772 个静态码点需下载 | 43 片 / **2192.9 KB** | 23 片 / **1206.2 KB** |
   > | `font-display` | L1 用 `block`、其余 `swap`（混用；`block` 会阻塞首屏文字渲染） | 全部 `swap` |
   > | 码点覆盖 | 770 / 772（**缺 2 字**） | 772 / 772 |
   > | 包体 / 文件数 | 17.21 MB / 1270 | 4.31 MB / 101 |
   > | 维护 | 2023-02 停更 | `lastModified` 2026-01-07，字体版本 v40 |
   >
   > 两者是同一字型（Noto Sans SC = 思源黑体 SC 的 Google 发行名），观感一致，故换包不改变本条的设计意图。
   > **⚠️ 供发起人行使 §4-5 目视否决权的成本事实**（实测，非估算）：即便选更轻的那个，全站静态 UI 文案也要拉 **23 个分片 / 1206.2 KB**（平均每片 52.4 KB），帖子正文是 UGC、含字更广会继续追加分片；`dist` 因 Vite 会把 CSS 引用到的 woff2 全量产出而**增加 4.31 MB**（浏览器只按 `unicode-range` 下命中的那部分，但部署产物变大）。而被替换掉的系统栈在 Windows 是微软雅黑、macOS/iOS 是苹方，**两者本身都是高质量中文字面、下载 0 字节**。这是本批"观感收益 vs 体积成本"的核心权衡。
5. **桌面 ≥768 全站走查 + 令牌扫尾**：9 真页 + 2 占位页逐页目视（**移动端一侧按 [CR-053](../../变更日志/变更台账.md#cr-053) 暂缓，本轮不做**），对照 [PRD](../../需求/产品需求文档.md) §5.1 确认无断链；复测全站无字面 hex / 无 `text-[Npx]` / 字重仅 400·500。**可选（请发起人点头才做）**：重摄 `docs/设计/UI规范/screenshots/` 的桌面 6 张（现档已双重过时：色值随 [CR-024](../../变更日志/变更台账.md#cr-024) 过时、布局随 [CR-025](../../变更日志/变更台账.md#cr-025) 过时）。

| **移动端 / 窄屏走查与重摄** | [CR-053](../../变更日志/变更台账.md#cr-053) 已按发起人指示暂缓；已落地窄屏代码**不回退** |
| **后端任何一行、`openapi.json`、Flyway 迁移** | 本轮是纯前端展示层，与 [CR-052](CR-052-前端界面美化.md) 同边界 |
