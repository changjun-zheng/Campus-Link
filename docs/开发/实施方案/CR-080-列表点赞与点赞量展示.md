## 1. 目标

让帖子列表（首页 / 版块 / 搜索 / 我的收藏 / 他人主页）能**就地看到点赞量并就地点赞**，消除"点赞数早已下发到列表出参、前端却从不显示；要点赞必须先进详情页"的断档。

## 2. 范围

**立论取证（写方案前先核的三条事实，均已在当前树实测）**

- `PostSummaryVo.likeCount` 自 [CR-048](../../变更日志/变更台账.md) 就在出参里、`frontend/src/api/forum.ts:26` 的类型也有，但全仓 `likeCount` 的**渲染点只有详情页两处**（`PostDetailView.vue:407` 帖子、`:516` 楼层）⇒ 列表看不到点赞量不是后端缺料，是前端没消费；
- 列表出参**没有 `likedByMe`**（`ForumResults.PostSummary` 与 `PostSummaryVo` 都少这一列）⇒ 列表即便放按钮，也不知道该显示"已赞"还是"点赞"。**这是本 CR 唯一需要动契约的原因**；
- `POST /api/v1/posts/{id}/like` 返回 `{active, count}`，与"就地回填计数"完全对得上 ⇒ **零新端点、零迁移、零新依赖**。

- **做**：
  1. `PostSummary` 载体与 `PostSummaryVo` 各加 `likedByMe`，口径与 `PostDetailVo` 逐字一致（登录为真实状态、匿名恒 false）；
  2. `toSummaries(posts, viewerId)` 批量取已赞 id，复用既有端口 `LikeRepository.findLikedTargetIds`——**一页一次查询，不 N+1**；`viewerId == null` 时根本不调仓储；
  3. 5 个调用点随之透传 viewer：`listPosts` / `searchPosts` / `listMyFavorites` / `listFollowingPosts` / `listVisiblePostsByAuthor`；
  4. 前端 `PostListItem` 元信息行加「点赞 数」一项（与刚改好的 回复数 / 阅读数 同一行）：可点、已赞用主色、未赞用 `text-ink-meta`，点击后以响应 `count` 回填；**匿名点击不发请求**，直接提示并跳登录；
  5. 新增一枚 Tabler `thumb-up` 到 `src/assets/icons/` 并登记进注册表（图标体系已随 [CR-055](../../变更日志/变更台账.md) 批次③ 定为 Tabler / MIT，目录内 `LICENSE` 已在）。
- **不做**（防边界漂移）：
  - **收藏不进列表**——用户这次只要点赞，收藏已有独立页 `/favorites/mine`；
  - **`MyPostSummaryVo` 不加 `likedByMe`**——"我的帖子"那一屏不回答"我赞没赞过自己的帖"，且这张窄 VO 的存在理由就是"多 `status`、少互动计数"（[CR-071](../../变更日志/变更台账.md)）；
  - 不改 `POST /posts/{id}/like` 的语义、鉴权与限流；不新增端点；
  - **点赞不产生通知**（沿用 [CR-074](../../变更日志/变更台账.md) 关注不产通知的理由：新增通知 type 会牵出前端硬编码文案链）；
  - 详情页现有 `el-button` 不改样式，只保证它与列表读到的 `likeCount` 同源。

## 2.5 方案自检修订（v1.0 → v1.1，逐条对着当前树核过）

> ⚠️ 先声明评审性质：本轮"评估"与"实施"同属一个 AI 会话，**独立评审性为零**（与 [CR-070](../../评审/增量PRD评审纪要.md) 登记过的那条是同一类弱点）。以下四条靠的是**逐条读代码取证**而不是"看着没问题"。

- **R1 · `viewerIdOf` 已有两份私有拷贝，方案原样会写成四份**。实测：`PostController.java:200` 与 `ReplyController.java:85` 各有一份**逐字相同**的 `private static Long viewerIdOf(Authentication)`。原方案让 `FavoriteController` / `UserPostController` 再各抄一份 ⇒ 同构逻辑四处散落，将来"principal 非 Long 时怎么算"改一处漏三处。**改法**：在 `common/web/CurrentUser` 新增 `optionalId(Authentication)` 作单点，既有两份私有拷贝一并迁过来删掉。⚠️ 这条把 `CurrentUser` 纳入改动面，而 AGENTS「测试约定」明确"改了 `common/web/CurrentUser` 必须重生成快照"——本轮本来就要重生成，**代价不增**，但快照 diff 的归因面要多看一处。
- **R2 · 加字段是**编译期**破坏，不是断言期失败**。`PostSummary` 是 record，`ForumPublicReadTest` 与 `UserPostControllerTest` 里有按位置构造它的夹具 ⇒ 字段一加这两处直接编译不过。步骤顺序据此调整为**先改夹具与实现同批**，不得指望"跑一遍看哪里红"。
- **R3 · 一条已知滞后必须写在前头，不能事后补**：详情页点赞后返回列表，列表项的 `likeCount` / `likedByMe` **不会自动刷新**（列表拿的是上一次拉取的快照）。本 CR **接受该滞后**（下次进列表即正确），不做跨页状态同步——那需要一个共享的帖子互动 store，是另一件事、另一个 CR。
- **R4 · 匿名点击的判定不能依赖后端 401**。`api/client.ts` 会把后端提示原样透出，匿名调 toggle 用户看到的是"未登录（4001）"这类**错误文案**而非引导。据此：前端先读 `useAuthStore().token`（与 `PostDetailView.vue:30` 同源），**无 token 就不发请求**，给"登录后可点赞"的提示并跳 `/login`。

## 5. 验证

- **单测**：`ForumQueryApplicationServiceTest` 补 3 例——① 登录时批量集合正确落到每条 `likedByMe`；② **匿名一次仓储都不调**（用计数型替身断言，不靠"结果恰好是 false"）；③ 一页 20 条只发生**一次**已赞查询（防 N+1 回归）。既有夹具逐处补字段。基线数以本轮 `mvn verify` 实测为准（AGENTS 声明 343，先跑真值再报增量，不引用未实测的数）。
- **真机**：列表点赞同步 +1 并转主色、再点 -1 复原；刷新后与详情页 `likedByMe` 一致；匿名点击 → 提示 + 跳登录且**网络面板无请求**；`/u/32` 与 `/favorites/mine` 同组件生效。
- **契约**：`git diff openapi.json` **必然非空**（多一个 boolean 字段），判定按"删除行逐行归因 + 结构化比对"——预期**只有 `PostSummaryVo` 的 properties 新增**，operation 数 / 路径数 / tag 数一律不变；若出现任何一条 operation 变化即为越界，停下来查。
- **回归面**（逐条确认，不靠"看起来没事"）：
  - `GET /posts` 与 `GET /posts/search` **仍是 `@PublicEndpoint`**：加的是可选身份，不是授权判定 ⇒ 匿名必须仍 200、`likedByMe` 恒 false；
  - 列表可见性过滤（`status` / 墓碑 / 热榜窗口）一行未改，下架帖仍掉出列表；
  - ⚠️ **共享 VO 加字段这条要单独交代**：[CR-071](../../变更日志/变更台账.md) 判过"不给 `PostSummaryVo` 加 `status`，否则把只面向作者的状态泄漏到公开列表"。本 CR 加的 `likedByMe` 不违反那条判断，因为它是 **viewer 侧、对任何登录者同构**的字段，其真值由服务端按当前令牌计算、**不来自被读内容本身**，不存在"谁能看到什么"的口径外溢；`status` 的问题恰恰相反——它是内容侧属性，一旦进共享 VO 就对所有读者下发。

### 7.1 与计划的偏差（四条，均如实记）

1. **改动面比 §3 多一个文件**：§3 未列 `backend/.../forum/web/UserPostController.java` 的**守护测试**`UserPostControllerTest`。它原本用"方法签名不收 `Authentication`"来守"他人主页匿名可读"，而本轮该端点必须收 `Authentication` 才能取可选身份 ⇒ **测试与本轮设计正面冲突**。处置：**改判据、不删测试**——新判据断言 `@PublicEndpoint` 在、`@SecurityRequirement` 不在、签名收 `Authentication`，并加一条行为断言"`controller.userPosts(id, 1, 20, null)` 仍返回数据"。⚠️ 这条改动的代价要说清：判据从"结构上不可能需要登录"换成"注解成对 + 传 null 仍可读"，**守住的东西没变**（匿名必须读得到），但"靠签名挡着"这层冗余没了。
2. **同批补做别人欠的契约同步**（超出 §2 范围）：§5「契约」一格原写"operation 数 / 路径数 / tag 数一律不变；若出现任何一条 operation 变化即为越界，停下来查"。**实测出现了 4 条**——逐条查证后确认**不由本 CR 产生**：[CR-077](../../变更日志/变更台账.md)（相似帖推荐）与 [CR-078](../../变更日志/变更台账.md)（他人主页 + 单条已读）落地时**根本没重生成快照**，那 4 个 operation 自始不在归档里。停手等的结论是"越界的是那两轮，不是本轮"，于是把它们的欠账一并补进 v1.15，并在[契约 README](../../设计/接口契约/README.md) §7 与台账 §4 三笔归因写清。⚠️ 顺带查出并修掉 [CR-077](../../变更日志/变更台账.md) 的一处瑕疵：`GET /posts/similar` 的 400 description 是 `参数错误（1001）；参数错误（1001）`——`@ErrorCodes` 显式写 `INVALID_PARAM` 与自动补的通用 400 撞车，**同一缺陷 CR-049 v1.8 记过、CR-071 自修过一次、这是第三次**。
3. **`CurrentUser.optionalId` 按计划落地并删了两份拷贝**（R1），但**AGENTS 与台账此前都未记载那两份拷贝的存在**，收敛属于本轮新发现的事实，已写入技术方案 §5 的 v0.7.18 头部注。
4. **§3 里"界面规范：图标清单补一行"这一格作废**：[界面规范](../../设计/UI规范/界面规范.md) **从来没有图标清单那一节**（图标数只写在 `src/assets/icons/index.ts` 的注释里），本轮不为一枚图标新起一节；该格改为在该档 §5.1 追加两样东西（元信息行**现行顺序**的回写 + 首次立"列表项内可放可点击控件"的三条前提），档升 **v1.10**。
