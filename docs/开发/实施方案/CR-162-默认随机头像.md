## 1. 目标

注册成功后按 **userId 取模**映射到 24 张既有头像之一（同一用户永久稳定），并把头像打通到论坛列表 / 详情 / 楼层；存量账号回填。**量化口径**：新增用户 `avatar_url` 命中 `/avatars/avatar-XX-*.png` 且 `(userId % 24)` 对应；回填后开发库 `avatar_url IS NULL` 的用户数 = **0**；论坛三个读接口的出参含 `authorAvatarUrl`，匿名帖该字段为 `null`。

## 2. 范围

- **做**：
  - **分配规则（问题 1）**：新增 `account.domain.model.DefaultAvatar`——**固定 24 项**路径数组（`/avatars/avatar-01-terminal.png` … `avatar-24-globe.png`，文件名即清单，**运行时不扫目录、不读文件**）；`forUser(long userId)` 取 `Math.floorMod(userId, 24)`（纯函数、不依赖随机数与时间）。`id % 24 == 0`（如 24 / 48）映射到 `avatar-01`。
  - **注册写入**：`AccountApplicationService.register`（`:85`）在 `accountRepository.save` 拿到自增 id 后计算头像，`AvatarCatalog` → `repository.updateAvatarIfAbsent(id, path)`（**只写 `avatar_url IS NULL` 的行**，绝不覆盖未来可能的用户自选 / 上传头像），并把值回填到聚合，使**注册响应**（`UserVo.avatarUrl`）立即带图；三步同处既有 `@Transactional`。
  - **存量回填（问题 2）**：新增 `backend/scripts/data/D004__backfill_default_avatars.py`（PyMySQL，**默认 dry-run、`--apply` 才写**），规则与 Java 侧**同一映射**；只更新 `avatar_url IS NULL`，幂等；**45 个开发账号 + admin 一并回填**（admin 也是平台用户、列表/详情需要一致观感；如要保留"管理员无头像"，只需在脚本排除 id，Java 侧注册仍照常）。
  - **论坛批量取值（问题 3）**：把 `AccountApplicationService.nicknamesOf`（`:199`）升级为 `authorBriefsOf(Collection<Long>) → Map<Long, AuthorBrief>`，`AuthorBrief(nickname, avatarUrl)` 放在 **account.application** 只读模型；底层仍是**一次** `accountRepository.findByIds`，**不做 N+1、不跨上下文 join**。更新 5 处调用：`ForumQueryApplicationService` 三处（详情 `:166`、楼层 `:225`、摘要 `:571`）、`NotificationApplicationService:130`、`AdminContentSearchApplicationService:69`（后两者只取 `.nickname()`）。
  - **论坛出参**：`PostSummary` / `PostDetail` / `ReplyItem` 三处加 `authorAvatarUrl`，`PostSummaryVo` / `PostDetailVo` / `ReplyVo` 同步；列表（含收藏 / 搜索 / 关注 Feed / 他人主页共用 `toSummaries`）、详情、楼层各自从**同一批** `authorBriefsOf` 取昵称与头像。
  - **匿名脱敏（问题 4）**：沿用 `ForumQueryApplicationService:164` 先例——`post.isAnonymous()` 时昵称取 `ANONYMOUS_NICKNAME`、**`authorAvatarUrl = null`**；列表与详情两处都要显式置空（不回填真实头像）。回帖本身无匿名能力，楼层不需要分支。
  - **契约（问题 5）**：三个 VO 各加一个可空属性 ⇒ `PostSummaryVo` / `PostDetailVo` / `ReplyVo` 三个 schema 变更（**零新增端点 / 路径 / tag**）；按[契约 README §2](../../设计/接口契约/README.md) 命令重抓 `docs/设计/接口契约/openapi.json`、`git diff` 非空即同步**技术方案 §5** 与契约 README 版本行；T1 / T2 快照测试必须变绿。
  - **前端**：`src/api/forum.ts` 三个接口加 `authorAvatarUrl: string | null`；`PostListItem.vue`（`:114`）与 `PostDetailView.vue`（`:443` / `:447` / `:590`）把 `:src` 传给既有 `UserAvatar`——该组件**已支持 src 优先、空值回落昵称首字**，不改回退逻辑，只更新头部注释里"当前恒为空"的事实描述。
- **不做**：**不生成 / 不重画 / 不压缩任何图片**（24 张 256×256、244KB 原样入库，`public/avatars/` 只加 `git add`）；不加依赖；不改 `tokens.css`；不做上传 / 裁剪 / 用户自选；不改通知 / 组队 / 私信的取图方式（它们已各自 join `users.avatar_url`）；不做 CDN / 懒加载 / 热榜索引；不把头像塞进 JWT。

## 5. 验证

- **单元 / 集成**：映射稳定性（同 id 恒同图、24 张全覆盖、floorMod）；注册写入且不覆盖非空；论坛解析无 N+1（mock 校验 `findByIds` 调用次数）；匿名帖头像必为 `null`；`SPRING_IT=true mvn -o verify` 全绿。
- **数据**：`SELECT COUNT(*) FROM users WHERE avatar_url IS NULL` 回填后 **0**；`SELECT id, avatar_url` 抽查 id 1 / 24 / 25 与 `id % 24` 一致；脚本复跑 `updated=0`。
- **接口**：`GET /api/v1/posts`、`/posts/{id}`、`/posts/{id}/replies` 均含 `authorAvatarUrl`；匿名帖为 `null`；契约 T1 / T2 绿；`git diff openapi.json` 只有属性级新增。
- **前端**：`npm run lint` / `build`；真实浏览器（1440 / 375）首页 / 版块 / 详情 / 楼层头像渲染、无 404、匿名帖显示首字占位；注册后顶栏头像立即更新。
- **边界**：本地回环 + 开发库；不验证真实上传 / CDN。

## 6. 回滚

- 代码：`git revert` 该提交；契约快照同轮回退并重抓。
- 数据：回填脚本只写 NULL，回退可 `UPDATE users SET avatar_url=NULL WHERE id IN (…)`（按脚本输出清单）；**不删 `public/avatars/`**（素材为发起人提供）。
- 注册新用户：停用本 CR 后新账号 `avatar_url` 为空，前端自动回落昵称首字，不影响可用性。

## 7. 风险

- **同图碰撞**：24 张 > 试点期用户量级，取模必然多人同图；这是"默认头像"的预期，不做唯一性约束。
- **部署 base 路径**：头像用 `/avatars/...` 绝对路径，与 `favicon.svg` / logo 同口径；若 A3-8 部署形态确定后配置了非根 `base`，需随 `servers` 一并复测。
- **并发写**：`updateAvatarIfAbsent` 带 `avatar_url IS NULL` 条件，重复注册事务重试 / 管理端并发写不会互相覆盖；`updated_at` 仅在真写时推进。
- **匿名泄露**：所有出参在服务端置空，前端只认服务端字段；不提供"按昵称在前端推导真实头像"的路径。
- **回填时机**：脚本对运行中的应用安全（单列 UPDATE），但建议低峰执行并由输出清单留痕。
