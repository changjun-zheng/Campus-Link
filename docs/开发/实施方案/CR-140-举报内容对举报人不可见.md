## 1. 目标

兑现主 PRD **F-SAFE-002** 验收第二句：**"被举报内容对举报人即时不可见"**。

现状取证：`ReportApplicationService#submit` 的注释自陈"被举报内容对举报人即时不可见由读侧后续 CR 承接"——CR-082 只交付了建单、24h 去重与工单闭环，**读侧过滤从未实现**，举报人提交后内容照常可见。本 CR 只补这一句，不改举报提交与工单处理本身。

## 2. 范围

**做**（登录态 viewer、`PENDING` 工单、本人视角）：

- 举报目标为 **POST**：该帖子从以下出口剔除——全站 / 版块列表（含 `sort=hot`）、搜索、关注 Feed、他人主页帖子流、相似帖推荐、**帖子详情（统一 3001）**；我的收藏页内剔除。
- 举报目标为 **REPLY**：该楼层从帖子楼层列表剔除（`total` 同源 -1）；引用摘要里不再渲染。
- 工单 `CLOSED` 后自动解除：`REMOVE` 的内容本身已下架 / 封禁；`DISMISS` 的内容对举报人恢复可见。
- 前端：举报成功后立即刷新——帖子举报 → 详情重新加载进入 3001 空态；楼层举报 → 楼层列表刷新、该楼层即时消失。

**不做**（逐条给理由）：

- **USER 类举报不触发任何隐藏**：用户对象没有"内容"可隐，做等价于单向拉黑，属另一条语义（CR-129 已提供用户主动拉黑）；
- **我的帖子 / 我的回帖不过滤**：本人视角的管理页，"自己举报自己"无产品意义；
- **通知摘要不过滤**：只回标题 / 楼层号，且内容本体已不可读（CR-066 既有口径）；
- 不新增端点 / 入参 / 错误码 / 迁移；不改 24h 去重与工单状态机；不做"因举报被隐藏"的可见提示（不向举报人暴露运营状态）。

## 3. 改动点（文件级）

- `forum/domain/gateway/PostRepository.java` + `PostRepositoryImpl.java`：`findPage` / `search` / `findPageByAuthors` / `findSimilar` 增加 `excludedPostIds` 参数（空集合短路，SQL 侧 `NOT IN`，`total` 同源）；

- `forum/application/ForumQueryApplicationService.java`：新增 `reportedTargetsOf(viewerId)` 一次取；接入列表 / 搜索 / Feed / 主页 / 相似帖 / 详情 / 楼层 / 引用 / 收藏九处；

**前端**：
