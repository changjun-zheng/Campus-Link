## 1. 目标

补齐 F-SOC-002 的剩余验收面：他人主页资料卡的「粉丝 / 关注」两个数字目前只是不可点的计数，本轮让它们成为入口，并提供两个分页列表端点与页面，走通「关注 → 出现在对方粉丝列表 → 取关消失」。

## 2. 范围

- **做**：
  - 两个**受保护**端点：`GET /api/v1/users/{id}/followers`、`GET /api/v1/users/{id}/following`，`page` / `size`（默认 1 / 20，上限 100），按关注时间倒序、`id DESC` 稳定次序；
  - 条目字段：`id` / `nickname` / `major` / `bio`（从 `users` 取，**不碰** `email_*` / `phone_*` / `student_id_*` / `role` / `status`）；
  - 目标不存在或已注销 → `404 / 2007`；条目**剔除已注销账号**（保证「列出来就点得开」）与 **viewer 已拉黑的账号**（与 [CR-129](../../变更日志/变更台账.md#cr-129) 读侧口径一致）；两处过滤都在 SQL 侧，`total` 与页内容同源；
  - `FollowRepository` 端口新增 4 个分页 / 计数方法，`FollowMapper` 用 `@Select` JOIN `users` + `NOT EXISTS user_blocks`；
  - 前端两条路由 `/u/:id/followers`、`/u/:id/following`（`requiresAuth`）复用同一 `FollowListView.vue`；资料卡「粉丝 / 关注」计数改 `RouterLink`；列表条目点进 `/u/:id`；「加载更多」分页；空态文案；
  - 契约快照重抓（预期 +2 操作 / +2 路径 / +2 schema），接口契约 README §3.5、技术方案 §5、界面规范、台账、驾驶舱回置。
- **不做**：
  - 列表条目内嵌关注 / 取关按钮（避免每条携带 viewer 关系与 N+1 请求，点进主页再操作）；
  - 粉丝 / 关注列表的匿名访问（受保护；匿名点计数由路由守卫跳登录回跳）；
  - 关系搜索 / 排序切换 / 互相关注标识；
  - 已注销账号的占位展示（直接剔除）；
  - 关注产生通知（[CR-074](../../变更日志/变更台账.md#cr-074) 既有口径不变）；
  - 列表 `total` 与 `follow-state` 计数的口径统一——前者是「可点开的条目数」（剔除已注销 / 拉黑），后者是「关系事实数」（不过滤），差异写入契约 README。

## 5. 验证

- **单测**：基线 **553**（默认 5 例 SKIPPED；`SPRING_IT=true` 0 SKIPPED）→ 预计 **+6~8**；新增「匿名 → 401」两例（AGENTS 约定）。
- **真机**（真实后端 + 真实库）：
  - B 关注 A → `GET /users/{A}/followers` 含 B、`GET /users/{B}/following` 含 A；
  - B 取关 → 两处列表均不含；
  - A 拉黑 B 后以 A 登录查自己的粉丝列表 → 不含 B；B 登录查 A 的粉丝列表 → 按 viewer 口径不含 A 拉黑的人；
  - 目标不存在 / 已注销 → `404 / 2007`；匿名 → `401 / 4001`；`page=0` / `size=999` 归一；
  - 已注销账号从列表剔除后 `total` 与页内容一致（SQL 同源）。
- **真实浏览器**（按 AGENTS「桌面前端功能必须真实浏览器验收」）：A 主页 → 点「粉丝」→ 列表出现 B → 点条目回 `/u/{B}` → 切「关注」Tab → 加载更多 → 空态文案；匿名点计数 → 登录页带回跳。
- **契约**：`openapi.json` 预期 `+2` 操作 / `+2` 路径 / 新增 `FollowUserVo` 与包装 schema；用契约 README §2 命令重抓后 `git diff` 核对。

## 8. 实施结果（实施后追加，不回改上文）

- **与计划一致**：端口 4 方法 + `FollowMapper` 4 条 `@Select` + 适配器、`FollowApplicationService.pageFollowers / pageFollowing`、`FollowUsers` / `FollowUsersVo`、`FollowController` 两个端点、前端 `api/follow.ts` + `FollowListView.vue` + 两条路由 + 资料卡计数改链接，均按 §3 落地；§7 四条口径按默认值执行（受保护 / 已注销剔除 / 两条路由复用组件 / 条目不带关注按钮）。
- **偏差 1（契约副作用，实测后修正）**：新控制器方法原名 `following`，与既有 `GET /posts/following` 的 springdoc `operationId` 撞车——重抓快照时既有端点被自动改名 `following_1`（`git diff` 出现 1 行删除）。改名 `followingUsers` 后重抓，快照恢复**纯新增**（+253 / −0）。契约 README §3.5 已写明该约束。
- **偏差 2（静态扫描）**：`FollowUsers` / `FollowUsersVo` 触发 SpotBugs `EI_EXPOSE_REP / REP2`（record + List），按既有第 ③ 组「不可变值载体」惯例加入 `spotbugs-exclude.xml`（2 类 × 2 条），未做防御性拷贝。
- **验证实测**：`SPRING_IT=true mvn -o verify` **553 → 567**（0 failures / Skipped 0）+ SpotBugs 0；`npm run lint` exit 0、`npm run build` 通过；契约 **v1.30**（45 路径 / 52 操作 / 80 schema / 39 受保护、152212 字节、+253 / −0）。
- **真机取证（真实后端 + 真实库）**：B 关注 A → A 粉丝列表 total=1（id 37）、B 关注列表 total=1（id 36）；取关 → 0；A 拉黑 B → **A 视角 total 1 → 0**（SQL 同源，应用层剔除会是 total=1 / items=0）、B 视角仍 1（单向语义）、解除恢复；分页 `size=2`：page1 `[39,38]`、page2 `[37]`（total=3）；SQL 造一行「已注销账号（id 76）关注 A」→ total 仍 **3**（剔除生效），**测后已删除该行**、关注关系全部清理为 0；匿名 `401 / 4001`、目标不存在 `404 / 2007`、`page=0&size=999 → 1 / 100`。
- **真实浏览器验收（两轮）**：① 登录态 6 步全 PASS（登录 → `/u/37` 资料卡「粉丝 0 / 关注 1」均为可点链接 → 点「关注」进 `/u/37/following` 见「模拟学生05」→ 点条目回 `/u/36` → A 主页点「粉丝」进 `/u/36/followers` 见「模拟学生06」、Tab 高亮正确）；② 匿名态 3 步全 PASS（清 localStorage 后访问 `/u/36/followers` 跳 `/login?redirect=/u/36/followers`；公开主页 `/u/36` 仍可开、计数仍可点）。控制台仅 `notifications/stream` 的 `ERR_ABORTED`（页面卸载正常中断，非功能错误）。
- **遗留**：列表条目不带 viewer 关注态（方案 D4）；「粉丝 / 关注」资料卡数字与列表 `total` 口径不同（已在契约 README、界面规范、VO javadoc 三处写明）。
