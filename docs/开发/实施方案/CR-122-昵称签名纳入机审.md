## 1. 目标

把**昵称 / 签名**接入与发帖、回帖**同一套** `ModerationGateway`：本地词表模式（`campuslink.moderation.mode=local`）下命中即 `5001 / 422`；未来 A3-8 的服务商适配器只要实现同一端口，昵称 / 签名自动获得同等审查，不需要再改 account 侧。

现状取证：`AccountCommands` 已有字符集与引流禁则（CR-071 / CR-119），但 `AccountApplicationService.register` 与 `ProfileApplicationService.updateProfile` **从未调用机审端口**；`ProfileApplicationService` 的类注释还写着"无机审期间"。

## 2. 范围

**做**

- forum 应用层新增 `ModerationApplicationService.ensureAllowed(String...)`：命中 → `5001`，网关异常 → `5002`（与发帖 / 回帖同一 fail-closed 口径）；
- `AccountApplicationService.register` 对昵称调用；`ProfileApplicationService.updateProfile` 对昵称 / 签名调用（在限流之后、读库之前）；
- `POST /auth/register` 与 `PUT /users/me` 的 `@ErrorCodes` 补 `MODERATION_BLOCKED` / `MODERATION_UNAVAILABLE`；
- 单测覆盖 pass / 命中 / 网关异常 / account 侧调用与拦截；契约快照再生成。

**不做**

- 不覆盖 `major`（E-013 的范围是昵称 / 签名；专业字段是否纳入另议）；
- 不改发帖 / 回帖的既有 moderation 调用链；
- 不实现真实服务商适配（A3-8 外部决策）；不把候选③ 的文字约定变成机器强制。

## 5. 验证

- `SPRING_IT=true mvn -o verify` 全绿（基线 515 + 新增用例），SpotBugs 0；
- 单测：本地词表命中昵称 / 签名 → 5001；网关异常 → 5002；log 模式放行；
- 真机：local + 词表下修改签名为含违禁词 → `422 / 5001`，正常签名 → 200；匿名 `PUT /users/me` 仍 `401 / 4001`；
- 契约：`PUT /users/me` 与 `POST /auth/register` 新增 422 / 503 声明；快照机器比对通过。

## 6. 回滚

- 移除两个应用服务中的 `ModerationApplicationService` 注入与调用、删除新增类与测试；
- 回退两个 Controller 的 `@ErrorCodes` 两项；
- 无迁移、无新依赖，回滚不影响既有账号数据。

## 7. 实施结果（2026-10-23）

**与原计划一致**：新增 forum application 的 `ModerationApplicationService`；`register` 在任何副作用前校验昵称，`updateProfile` 在限流后、读库前校验昵称 / 签名；两个 Controller 补 `5001 / 5002` 声明；无迁移、无新依赖。

**验证证据**

- `SPRING_IT=true mvn -o verify` **521 / 0 failures / 0 errors / Skipped 0** + `BugInstance size is 0`（基线 515 → 521：机审入口 4 例 + 注册 / 资料各 1 例）；
- **真机（log 模式）**：签名含"违禁词"仍 `200`——log 通道只记录放行，默认行为未变；
- **真机（local 模式 + `MODERATION_WORDS=违禁词`）**：`PUT /users/me` 的违规签名 → `422 / 5001`，正常签名 → `200`；`POST /auth/register` 的违规昵称 → `422 / 5001`（票据 / 验证码未被消费）；
- **契约 v1.25**：`POST /auth/register` 与 `PUT /users/me` 各新增 `422 / 5001` 与 `503 / 5002`，快照 **44 操作 / 39 路径 / 69 schema / 31 受保护**、diff **+40 / −0 纯新增**。

**偏差如实登记**
