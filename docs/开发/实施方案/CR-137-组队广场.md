## 1. 目标

把 PRD 仅有一行的 F-TEAM-001 落成可闭环的组队广场：登录用户发布招募（方向 / 目标赛事 / 人数 / 截止 / 联系方式），其他学生申请加入、发起人审批；满员自动停止招募，发起人可关闭。列表与详情匿名可读，联系方式仅发起人与已加入成员可见。

## 2. 范围

**做**

- 新建 `module/team` 限界上下文（照抄 `module/messaging` 的 domain / application / infrastructure / web 四层，ADR-012）；
- 新增 `V8__teams.sql`：`teams`（招募主体）+ `team_members`（发起人 / 申请 / 成员，联合主键）；
- **8 个端点**：2 个公开（列表 / 详情）+ 6 个受保护（发布 / 申请 / 申请列表 / 审批 / 关闭 / 我的组队）；
- 业务口径：方向固定枚举 7 项、人数 2~20（含发起人）、满员自动 `FULL`、发起人可 `CLOSED`、被拒不可再申请、不能申请自己的组队、关闭不可重开；
- 错误码新开 **6xxx** 段：`6001` 组队不存在 / `6002` 已停止招募 / `6003` 名额已满 / `6004` 已提交过申请 / `6005` 不能申请自己的组队 / `6006` 申请不存在；
- **联系方式 AES-GCM 加密存 `contact_enc`**（复用 `common/crypto/CryptoService`），仅发起人与已加入成员可见；
- 机审复用 forum `ModerationApplicationService.ensureAllowed`（标题 / 简介 / 目标赛事；联系方式只做长度与禁尖括号校验）；
- 前端 4 个路由（`/teams`、`/teams/new`、`/teams/:id`、`/teams/mine`）+ 顶栏「组队」入口 + `api/teams.ts`；
- 契约快照重抓、技术方案 / ER 图 / 界面规范 / PRD §5.1 / 台账 / 驾驶舱同步。

**不做**

- 组队与论坛帖子互联（不自动在「竞赛交流」发帖、不挂帖子 ID）；
- 通知（申请与审批结果在「我的组队」页可见，登记为残余）；
- 成员主动退出 / 发起人移除成员 / 转让发起人 / 解散组队 / 编辑组队；
- 关闭后重开、截止日期到期自动结束（不新增定时任务）；
- 群聊 / 举报单条 / 搜索与热度排序 / 复用 `tags` 标签体系 / 匿名发起。

### 8.3 已知边界

- 通知未接入：申请与审批结果只在「我的组队」页可见（方案 D7）；成员退出 / 移除 / 转让 / 重开 / 编辑组队 / 截止自动结束均未做。
