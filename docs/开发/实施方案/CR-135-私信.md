## 1. 目标

补 PRD P1「私信」（F-SOC-003）的最小可验收形态：登录用户之间**一对一纯文本私信**——会话列表、消息分页、发送、已读、未读角标；与既有拉黑（[CR-129](../../变更日志/变更台账.md#cr-129)）和机审（F-SAFE-001）联动。用**新建 `module/messaging` 限界上下文**承载，照抄 `module/{account,forum}` 四层结构（ADR-012），不在 forum / notification 里混入私信职责。

## 2. 范围

- **做**：
  - **迁移** `V6__direct_messages.sql`：`conversations`（`pair_low_id` / `pair_high_id` 归一 + 唯一键，`last_message_id` / `last_message_at`）+ `messages`（`conversation_id` / `sender_id` / `receiver_id` / `content` / `created_at` / `read_at`），含主键 / 唯一键 / 三个查询索引 / 外键。
  - **新上下文 `module/messaging`** 四层：`domain`（`Conversation` / `Message` / 端口 `ConversationRepository` / `MessageRepository`）→ `application`（`MessagingApplicationService` + Command / 分页载体）→ `infrastructure`（MyBatis-Plus 仓储 + Mapper + DO）→ `web`（`MessageController` + VO）。
  - **5 个受保护端点**（`@SecurityRequirement(BEARER_AUTH)` + `CurrentUser.requireId`）：
    - `GET /api/v1/messages/conversations?page=&size=` —— 会话列表，按 `last_message_at DESC`；条目 `peerId / peerNickname / peerAvatarUrl / lastMessagePreview（纯文本前 50 字）/ lastMessageAt / unreadCount`；
    - `GET /api/v1/messages/{peerId}?page=&size=` —— 与某人的消息**倒序**分页（最新在前）；无会话返回空页（不报错）；
    - `POST /api/v1/messages/{peerId}` —— 发送 `{content}`（**纯文本 1~1000 字**）；首次自动建会话并把 `last_message_*` 指到新消息；
    - `POST /api/v1/messages/{peerId}/read` —— 把该会话中 `receiver_id = 我 AND read_at IS NULL` 的消息置为已读；
    - `GET /api/v1/messages/unread-count` —— 我的未读总数（顶栏角标）。
  - **业务口径**：不能发给自己（新增 `CANNOT_MESSAGE_SELF(2015, 400)`）；目标不存在 / 已注销 `2007 / 404`；**双向拉黑**（任一方向 `isBlocked` 为真）`4002 / 403`；内容过 forum `ModerationApplicationService.ensureAllowed`（命中 `5001 / 422`、异常 `5002 / 503`）。
  - **分页归一**：`page ≥ 1`、`1 ≤ size ≤ 100`（会话列表与消息列表同口径），`total` 与页内容同 WHERE。
  - **前端**：`/messages` 会话列表页 + `/messages/:peerId` 聊天页（气泡 / 加载更早 / Enter 发送 / 自动滚底 / 进入即已读）+ `App.vue` 顶栏「私信」入口与未读角标 + `ProfileView` 他人主页「私信」按钮；`useUnreadMessages` 30 秒轮询 + 发送后刷新；新增 `mail` / `send` 两个 Tabler SVG。
  - **契约与文档**：快照重抓（预期 **+5 操作 / +5 路径 / +6 schema / 新 tag `message`**）；技术方案 §2.4 目录树 + §4.1 两张表 + §5 五行；ER 文档 §2~§5（**14 → 16 张**）；界面规范新增私信页约定；台账 / 驾驶舱回置。
- **不做**：
  - 群聊 / 附件 / 图片 / 语音 / 消息撤回 / 编辑 / 删除单条消息；
  - **实时推送**（SSE / WebSocket）——本轮只做 30 秒轮询 + 发送后即时刷新，后续可复用 [CR-121](../../变更日志/变更台账.md#cr-121) 的 SSE 模式；
  - 消息全文搜索、举报单条消息、会话置顶 / 免打扰 / 黑名单内单独放行；
  - 拉黑后历史消息删除或隐藏（历史对双方仍可见，只禁止后续发送）；
  - 陌生人首条消息的「请求 / 接受」审批（PRD 无依据，且与拉黑能力重叠）。

## 4. 步骤

1. `V6` 迁移 + domain 模型 / 端口；真实启动一次确认 Flyway（`mvn verify` 不校验迁移可执行性）。

### 8.2 验证证据（真机 / 浏览器 / 契约）

- **全量测试**：`SPRING_IT=true mvn -o verify` → **637 / 0 failures / 0 errors / Skipped 0**，`BugInstance size is 0`，BUILD SUCCESS。
- **真机双账号（A=32 / B=33）**：A 连发 3 条 → B 会话列表 `total=1 / unreadCount=3 / lastMessagePreview=第 3 条`、消息分页倒序 `3|2|1`；B 标记已读 `updated=3` → B 未读 0、A 未读恒 0；自聊 `400 / 2015`；目标不存在 `404 / 2007`；`page=0&size=999 → page 1 / size 100`；A 拉黑 B 后双方发送均 `403 / 4002` 且 B 历史 `total=3` 仍可读；解除后发送恢复；空白 `400 / 1001`、1001 字 `400 / 1001`；匿名 `POST` `401 / 4001`。

### 8.3 已知边界

- 无 SSE：未读角标靠 **30 秒轮询 + 发送 / 已读后主动刷新**，最长 30 秒延迟（D5）。
- 拉黑只禁止后续发送；历史消息双方仍可读，且会话列表**不剔除**已拉黑 / 已注销对方（否则用户会找不到历史聊天记录）。
- `GET /messages/{peerId}` 不校验目标是否存在（无会话返回空页），这是"从主页点私信直接写第一条"的前提；发送时才做 `2007` 校验。
- 会话列表与消息分页的 `total` 与页内容同 WHERE（仓储 SQL 单点），但尚未像 CR-129 那样把「未读子查询」抽成共享片段；未来加过滤条件时两处须同改。
