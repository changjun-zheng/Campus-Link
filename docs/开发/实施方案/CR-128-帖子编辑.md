## 1. 目标

让作者编辑自己**未删除、未下架**的帖子：标题 / Markdown 正文 / 标签可改，**版块不可改**。发布时的机审、Markdown 渲染、封面提取、标签规范化口径全部复用，不另起一套规则。

## 2. 范围

**做**：两个受保护端点（取编辑原文 / 提交编辑）、作者校验、状态校验（仅 `PUBLISHED` 且未删）、标题 / 正文 / 标签机审、标签关联替换、`POST_UPDATE` 审计、前端编辑页（复用发布页）与详情页「编辑」入口。

**不做（逐条给理由）**：

- **编辑历史 / 版本 / 「已编辑」标记**：PRD 未要求，需新表 + 迁移，成本与收益不匹配；如需要另开 CR。
- **改版块**：版块决定路由与列表归属，变更会让历史链接与订阅语义漂移；另开 CR。
- **编辑已下架 / 已删除帖**：下架是平台处置，恢复后即可编辑；删除是墓碑，无恢复能力。
- **并发版本锁**：`posts` 无 version 列；定向 UPDATE 带状态条件，同一作者并发编辑为后写覆盖（登记为已知残余）。
- **编辑后重算热榜 / 通知订阅者**：编辑不是互动，热榜公式输入（时间窗与计数）不因正文变化而变；不打扰订阅者。

## 3. 改动点（文件级）

**后端（forum）**

- `domain/model/Post.java`：新增 `revise(title, contentMd, contentHtml, coverUrl, tags)`，返回新聚合（不可变模式，同 `acceptReply`），标题 `trim()`。
- `domain/gateway/PostRepository.java`：新增 `boolean revise(...)`——定向 UPDATE `title / content_md / content_html / cover_url / tags`，条件 `id=? AND is_deleted=0 AND status='PUBLISHED'`；返回 0 行表示并发下已删 / 已下架。
- `domain/gateway/TagRepository.java`：新增 `replaceForPost(postId, names)`——先删该帖 `post_tags` 旧关联，再复用既有 find-or-create + 回写 `posts.tags`；**单个端口方法**，避免调用方编排两条 SQL。
- `application/cmd/UpdatePostCommand.java`：`title`（≤100、非空白）、`contentMd`（复用 `ContentLimits.MAX_CHARS`）、`tags`（0~5）。
- `application/PostApplicationService.java`：新增 `revisePost(authorId, postId, cmd)`——`assertActiveForContent` → `findById` 且 `isVisible`（否则 3001）→ 非作者 4002 → 标签规范化 + 标题 / 正文 / 每条标签各审一次 → 渲染 + 封面 → `post.revise(...)` → `postRepository.revise(...)`（0 行 → 3001）→ `tagRepository.replaceForPost(...)` → 审计 `POST_UPDATE`（detail 同 `POST_DELETE` 的版块 + 截断标题）。
- `application/ForumQueryApplicationService.java`：新增 `editablePost(postId, viewerId)`——仅作者，返回 `EditablePost{id, boardCode, boardName, title, contentMd, tags}`；非作者 4002、不可见 3001。
- `web/PostController.java`：`GET /{id}/edit`（受保护，取原文）+ `PUT /{id}`（受保护，提交）；两处 `@ErrorCodes` 各声明 4001 / 4002 / 3001 / 2006 / 2013 / 5001 / 5002。
- `web/vo/EditablePostVo.java`（新增）+ `application/cmd/ForumResults.EditablePost`。

**前端**

- `api/forum.ts`：`getEditablePost(id)` / `updatePost(id, payload)`。
- `router/index.ts`：新增 `/post/:id/edit`（`requiresAuth`）。
- `PublishView.vue`：按 `route.params.id` 进入编辑模式——预填标题 / 正文 / 标签，版块只读展示，隐藏相似推荐与草稿读写，提交走 `updatePost`，成功后回详情。
- `PostDetailView.vue`：作者操作区在「删除」旁加「编辑」。

**契约 / 文档**：`openapi.json` 再生成（+2 受保护 operation、+1 schema）；技术方案 §5 补两行；契约 README 版本；台账 / 驾驶舱 / AGENTS 基线数。

## 4. 步骤

1. 领域 `revise` + 两个端口方法 + 适配器实现（`PostRepositoryImpl` / `TagRepositoryImpl`）。
2. 应用服务 `revisePost` / `editablePost` + Command / 结果载体。
3. 控制器两个端点 + VO；补单测（成功 / 非作者 403 / 已下架与已删 3001 / 机审 5001 / 标签替换 / 0 行并发）。
4. 前端 API + 路由 + 两视图；`lint` / `build`。
5. 起栈真机：作者编辑 → 详情更新、旧标签消失；非作者 403；下架后 3001。
6. 契约重抓、diff 归因，同步文档。

## 6. 回滚

单提交 revert；**零迁移、零新依赖**。数据侧回滚代码后已有编辑结果保留（覆盖写，不产生新表 / 新列），属可接受残留。

## 7. 实施结果（2026-10-23，实施后回填；原计划正文一字未改）

**与计划一致**：两个受保护端点、`Post.revise`、`PostRepository.revise`（定向 UPDATE 带 `is_deleted=0 AND status='PUBLISHED'`，0 行 → 3001）、`TagRepository.replaceForPost`（旧关联与 `use_count` 回退后重挂）、`POST_UPDATE` 审计、前端 `/post/:id/edit`（版块只读 / 不写草稿 / 不查相似帖）与详情页「编辑」入口，均按 §3 落地；§2 的不做清单全部保持未做。

**与计划的偏差（如实登记）**：

1. **测试数**：计划预估约 8 例，实际新增 **7 例**（`PostApplicationServiceTest` 5 + `PostRepositoryImplTest` 1 + `TagRepositoryImplTest` 1），基线 530 → **537**（计划写"约 538"）。
2. **SpotBugs 排除 7 条（计划未预估）**：首次 `mvn verify` 因 `UpdatePostCommand` / `EditablePost` / `EditablePostVo` 的 `EI_EXPOSE_REP·REP2` 与 `PostApplicationService` 的 DI `REP2` 报红；按既有排除清单的判例 ③（不可变值载体，同 `PublishPostCommand`）与 ①（DI 注入误报）逐类补入并注明理由，复跑 `BugInstance size is 0`。
3. **契约 diff 非纯新增**：`git diff` **+356 / −80**，−80 行是 `/api/v1/posts/{id}` 整块在 `paths` 中的顺序位移（springdoc 按映射注册顺序输出）；**结构化比对确认既有 44 个 operation 与 69 个 schema 逐项零变化**，真实新增为 2 操作 + 3 schema（计划只写了"diff 仅新增"的预期，未预估位移）。
4. **真机机审验证方式**：以 `MODERATION_MODE=local` + `MODERATION_WORDS=违禁词` 启动一次后端，同时覆盖编辑成功链路与机审拦截，避免二次重启。

**验证结果**：`SPRING_IT=true mvn -o verify` **537 / 0 failures / Skipped 0** + SpotBugs 0；`npm run lint` exit 0、`npm run build` ✓；真机作者取原文 200、非作者 GET/PUT 403、编辑后详情标题 / 标签 / HTML 更新、标签编辑后搜索命中（编辑前 0 → 编辑后 1）、违禁词 `422 / 5001`、admin 下架后 GET/PUT 404；验证帖（id 58 / 59 / 60）删前已清理；契约 v1.28（40 路径 / 46 操作 / 72 schema / 14 tag / 33 受保护、135991 字节）。

**已知残余（与计划一致）**：同一作者并发编辑为后写覆盖（无 version 列）；编辑不重置 `hot_score`、不通知订阅者。
