## 1. 目标

把顶栏未读角标从"30 秒轮询"升级为**服务端推送**：通知落库并提交后，通过受保护的 SSE 长连接把最新未读数推到浏览器，兑现 PRD F-SOC-001 验收句"通知列表**实时可见**未读角标"。轮询保留为断线兜底，不作为主通道。

现状取证：`frontend/src/composables/useUnreadNotifications.ts` 只有 `POLL_INTERVAL_MS = 30_000`，注释自陈"没有实时推送就必然有滞后"；后端 `NotificationController` 只有 4 个普通端点，无流式通道。

## 2. 范围

**做**

- 受保护端点 `GET /api/v1/notifications/stream`（`text/event-stream`），令牌只走 `Authorization` 头，**不进 query string**；
- 应用层订阅注册表：按 userId 分组，每用户最多 5 条并发连接，超出时关闭最早一条；
- 通知落库后经 `@TransactionalEventListener(phase = AFTER_COMMIT, fallbackExecution = true)` 推送 `event: unread` + `data: {"unreadCount": n}`；
- 20 秒心跳注释帧 `: ping`（保活 + 让客户端区分"链路活着"与"有新通知"）；
- 前端 `fetch` 流式解析（可带 Authorization 头，EventSource 做不到）：断线 5 秒重连、登出即断开、30 秒轮询继续兜底；
- 服务端连接超时 30 分钟，客户端到期自动重连。

**不做**

- 不推送完整通知对象（铃铛只需计数，通知列表仍走既有分页接口）；
- 不做 WebSocket 双向通道、浏览器 Notification API、桌面推送；
- 不做多实例广播（内存注册表仅单实例；多实例需 Redis Pub/Sub，待 A3-8 部署形态决策后另开 CR）；
- 不改既有 4 个通知端点的路径 / 入参 / 出参 / 错误码。

## 7. 实施结果（2026-10-22）

**与原计划一致**：端点路径 / 事件名 / 心跳 / 每用户上限 / 前端重连与轮询兜底均按 §2 落地；新增 6 个后端类（订阅接口、注册表、事件、监听器、心跳触发器、SSE 适配器），无迁移、无新依赖。

**验证证据**

- `SPRING_IT=true mvn -o verify` **515 / 0 failures / 0 errors / Skipped 0** + `BugInstance size is 0`（基线 507 → 515：流服务 5 例、通知应用服务 +1、控制器 +2）；
- `npm run lint` exit 0、`npm run build` ✓ 16.31s；
- **真机 SSE**：匿名 `GET /api/v1/notifications/stream` → `401 / 4001`；带 token → `200 text/event-stream`，首帧 `event:unread data:{"unreadCount":0}`、心跳 `: ping`；A 建帖、B 回复后 **4 秒内**收到第二帧 `unreadCount=1`（验证帖已删除）；
- **浏览器（Vite 5173 代理）**：登录后 `/api/v1/notifications/stream` 连接活跃、3 秒后仍保持，控制台零错误；
- **契约 v1.24**：44 操作 / 39 路径 / 69 schema / 31 受保护，`+46 / −0` 纯新增。成功响应显式声明为 `text/event-stream` + `string`，避免把 `SseEmitter.timeout` 抄进契约。

**偏差如实登记**

- 首次 `mvn spring-boot:run` 因上一轮被终止的增量编译残留报 `NoClassDefFoundError`，`mvn clean compile` 后恢复；属环境噪声、与代码无关；
- 计划外的两处补充：SSE 适配器把 `IOException` 包成 `UncheckedIOException` 交给注册表摘除；控制器对 200 响应加了成功体注解（见上）。
- **未做**（计划内）：多实例广播 / Redis Pub/Sub —— 待 A3-8 部署形态决策后另开 CR。
