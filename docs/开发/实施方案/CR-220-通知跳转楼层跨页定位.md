## 1. 目标

PRD F-SOC-001 的验收句写着「点击通知跳转对应楼层」，但当前只对**第一页**成立：详情页带 `?floor=<replyId>` 进入时只加载第 1 页再按 DOM id 查找，回复在后续页时什么都不会发生。长贴（正是 CR-219 讨论的场景）里被通知的楼层几乎总在末页，跳转实际长期失效。本 CR 让服务端按楼层列表的同一排序与过滤算出目标楼层所在页，前端直接打开该页并高亮。

## 2. 范围

- **做**：
  - `GET /api/v1/posts/{postId}/replies` 新增可选查询参数 `focus`（回复 id）：命中同帖可见楼层时返回**该楼层所在页**（`page` 以响应为准），并继续套用拉黑 / 本人未闭环举报过滤；与 `page` 同时出现时 `focus` 优先。
  - `focus` 不存在、已下架 / 已删、属于他帖、或被当前访问者过滤（拉黑 / 举报）时**不报错**，按请求的 `page` 正常返回。
  - 前端详情页带 `?floor=` 时把该 id 作为 `focus` 传入首次楼层加载，用响应 `page` 同步分页器后再滚动 + 高亮。
  - 单测覆盖分页定位与全部回落分支；新增真库集成用例（`SPRING_IT`）；契约快照重生成并同步技术方案 §5。
- **不做**：
  - 不改通知表 / 通知出参（`floorNo` 继续保留，界面不展示的 CR-219 口径不变）。
  - 不改楼层排序（最佳答案置顶、其余 `floor_no` 升序）与分页大小上限。
  - 不做「定位到某层后自动清掉 URL 的 `floor`」或站内定位动画；不做楼层号恢复。

## 5. 验证

- **单测**：`focus` 命中第 3 页 → 仓储按第 3 页取数；他帖 / 不存在 / 已删 / 被拉黑 / 被举报 → 回落请求页；目标为最佳答案 → 第 1 页；匿名访问不额外查拉黑 / 举报。
- **真机**：25 条回复的帖子，通知链接指向第 22 条 → 打开即第 2 页、高亮该层；指向最佳答案 → 第 1 页置顶高亮；指向已删楼层 → 第 1 页且无高亮、无报错。
- **契约**：`git diff` 只应有 `focus` 参数与 `GET /posts/{postId}/replies` 的 summary 变化，操作 / schema / tag 数不变。
- **回归面**：普通翻页（无 `focus`）行为与响应形状不变；`floorNo` / `total` / 拉黑与举报过滤口径不变；通知跳转帖子的原有入口不受影响。

## 6. 回滚

纯前向新增可选参数：回滚 = revert 本 CR 提交即可，前端旧调用（不带 `focus`）与后端旧参数互不依赖；无迁移、无数据回补。若只想撤前端，可只回退 `PostDetailView` / `forum.ts`，后端保留无害。
