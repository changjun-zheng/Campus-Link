## 1. 目标

通知中心每条记录显示 **actor 头像（20px）**，与论坛列表 / 主页 / 关注列表统一使用 CR-162 的默认头像；**平台类通知**（`content_removed` / `content_restored`，界面文案固定为「平台」）**不渲染真实操作人头像**，避免把管理员身份暴露给普通用户。头像为空时仍回落昵称首字（`UserAvatar` 既有逻辑）。

## 2. 范围

- **做**：
  - `NotificationApplicationService.NotificationItem` 增加 `actorAvatarUrl`；`toItem` 使用与昵称**同一批** `authorBriefsOf` 结果（CR-162 临时把 Map 摊回昵称，本次改为保留 `AuthorBrief`，**仍一次 `findByIds`、无 N+1**）；**平台类型置 `null`**（不以管理员头像顶替）。
  - `notification/web/vo/NotificationVo` 加可空属性并透传；前端 `src/api/notification.ts` 类型加 `actorAvatarUrl?: string | null`；`NotificationsView.vue` 行首增加 `<UserAvatar :src="n.actorAvatarUrl ?? ''" :size="20">`，仅在 `n.actorAvatarUrl` 非空时渲染（平台类 / 空头像保持现状：未读点 + 文本）。
  - 契约：`NotificationVo` 一个 schema +1 可空属性，重抓快照（零新增端点 / 路径 / tag），同步技术方案 §5 与契约 README。
  - 测试：`NotificationApplicationServiceTest` 断言 actor 头像与平台类置空；VO 映射；契约 T1 / T2。
- **不做**：不改未读点、整行点击、已读逻辑；不改通知生成链路 / `NotificationType`；不做通知头像点击进主页（整行已是链接）；不改后台 / 论坛其他 VO；不动 `tokens.css`、不加依赖、不改数据库。

## 7. 风险

- **平台通知的隐私边界**：只置空头像还不够——界面文案已固定「平台」；本轮不额外隐藏 actorId（现状已下发 id，前端不展示）。
- **行高与密度**：20px 头像与现有未读点并排，行高略增；移动端 375 需复测换行。
- **空头像**：条件渲染保证不出现空 `img`；`UserAvatar` 回退逻辑保持不变。
