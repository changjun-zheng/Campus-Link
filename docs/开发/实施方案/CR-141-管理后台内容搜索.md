## 1. 目标

兑现主 PRD **F-ADMIN-002** 验收句："Given 管理员，When **按关键词 / 用户 / 时间搜索内容**，Then 可查看详情并执行处置动作（与 F-SAFE-003 联动）。"

现状取证：`AdminView.vue` 的内容处置台注释自陈"**搜索接口属 P1，MVP 用 id 精确操作**"——后台只能凭已知 id 下架 / 恢复；内容巡查队列（CR-133）只能按类型 + 时间倒序，**无关键词、无用户筛选**。本 CR 补齐"发现 → 查看 → 处置"这条链路。

## 2. 范围

**做**：

- 新增受保护端点 `GET /api/v1/admin/contents`（仅 SUPERADMIN，与现有处置端点同角色口径）：
  - `type`：`post` / `reply`，缺省 `post`，非法值归一 `post`（与巡查队列同口径）；
  - `keyword`：标题 / 正文 LIKE，2~50 字，空串视为不筛选；
  - `userId`：按作者精确筛选（可选）；
  - `days`：7 / 30 / 90（可选，按创建时间倒推；非法值 `1001`）；
  - 分页 `page` / `size`（短名、归一口径与全站一致）。
- 结果条目（帖子 / 楼层统一口径）：`id`、`type`、`title`（楼层为纯文本摘要）、`contentSummary`（纯文本前 200 字，供管理员判断，**不下发 HTML / Markdown 原文**）、`boardName`（帖子）/ `postTitle`（楼层）、`authorId`、`authorNickname`、`status`、`createdAt`。
- 可见性：**只列未删内容**；`status=PUBLISHED` 与 `REMOVED` 都列出（与巡查队列一致，便于恢复）；自删墓碑不列。
- 作者昵称：`userId` 精确取；另支持 `authorKeyword`（昵称 LIKE）→ 经 **account application** 解析为 id 集合后回传论坛侧筛选（跨上下文只调 application，ADR-012）。
- 前端：`AdminView` 内容处置台改为"搜索表单 + 结果表 + 就地处置"（复用既有 `moderatePost` / `moderateReply`），保留原有按 id 直达作为快捷入口。
- 契约快照再生成；技术方案 §5 / 界面规范补行。

**不做**：

- 不放开 OPS 角色（PRD F-ADMIN-001 的角色分工是独立事项，现所有管理端点仍仅 SUPERADMIN）；
- 不搜用户资料 / 举报工单（工单已有列表与状态筛选）；
- 不新增 FULLTEXT 索引 / 迁移（关键词走 LIKE，试点量级可接受；规模升级随 F-FORUM-009 的检索线另议）；
- 不做批量处置 / 导出 / 处置历史 / 独立详情页（结果摘要已够判断，处置仍走既有端点与审计）；
- 不改处置端点、错误码与审计口径。
