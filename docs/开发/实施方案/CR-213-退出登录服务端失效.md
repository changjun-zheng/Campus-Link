## 1. 目标

前端「退出登录」当前只清 localStorage，服务端 JWT 仍有效最长 7 天——用户点退出并不等于令牌失效。CR-208 已建立用户级吊销水位，但当时明确把退出登录端点排除在外。本 CR 新增 `POST /api/v1/auth/logout`：登录用户调用即把所有旧 token 水位推到当前时刻，旧 token 下一请求返回 `401 / 4001`。项目无多设备会话模型，退出即全端退出，与既有权衡一致。

## 2. 范围

- **做**：
  - 新增 `POST /api/v1/auth/logout`：受保护、无请求体、无返回数据；`CurrentUser.requireId` 取当前账号，调用 `tokenRevocationGateway.revokeAllBefore(id, now)`。
  - `AccountApplicationService.logout(long accountId)`：只写吊销水位，不记审计（非业务状态变更，避免刷屏）。
  - 前端 `auth.logout(notifyServer = false)`：显式退出（顶栏 / 设置页）传 `true`，先尽力发请求再清本地；401 / 过期路径保持不发请求。
  - 单测、契约快照、技术方案 §5、台账与驾驶舱同步。
- **不做**：
  - 不做逐设备 / 单 token 注销（JWT 无 jti 黑名单；退出 = 全端退出）；
  - 不新增退出登录审计事件、不改 JWT 格式与有效期、不新增迁移 / 错误码；
  - 不改 401 / 封禁 / 注销路径的既有自动清会话逻辑。

## 5. 验证

- **单测**：`logout` 只调用 `revokeAllBefore(id, ~now)` 一次，不写审计、不触达仓储；匿名调端点 → `4001` 且不触达用例；登录调用 → 200 且 id 透传。
- **真机**：用户 token 调 `POST /auth/logout` → 200；同 token 再访问 `/users/me`、`/notifications` → `401 / 4001`；重新登录获取新 token 正常。
- **前端**：顶栏与设置页退出后回首页；Network 可见 logout 请求；断网 / 500 时仍清本地并跳转。
- **契约**：重抓后仅新增 1 个 POST 操作（受保护），路径 / schema / tag 其余部分结构化零变化。
- **回归**：401 自动退出、封禁 / 注销清会话路径不变；登录 / 续签不受影响。

## 6. 回滚

revert 本 CR 提交即可；零迁移、零数据回补。已吊销的 token 会保留水位至自然过期，用户重新登录即可。
