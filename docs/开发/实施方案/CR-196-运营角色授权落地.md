## 1. 目标

兑现 PRD F-ADMIN-001 的角色最小集：**运营（OPS）可做内容审核与举报工单处理，超级管理员（SUPERADMIN）保留处置、封禁、名册、标签、看板与权限管理**。当前 11 个管理端点全部只认 `ROLE_SUPERADMIN`，`AccountRole.OPS` 枚举存在但没有可用入口。

## 2. 范围

- **做**：
  - 角色层级：`SUPERADMIN` 登录态同时持有 `ROLE_OPS` 权限，既有超管行为零变化。
  - 端点授权矩阵：
    - **OPS + SUPERADMIN**：`GET /api/v1/admin/contents`、`GET /api/v1/admin/review-queue`、`GET /api/v1/admin/reports`、`PUT /api/v1/admin/reports/{id}`。
    - **仅 SUPERADMIN**：名册导入、封禁 / 解封、数据看板、帖子 / 楼层处置、标签管理、角色授予。
  - 工单处理中的 `REMOVE` 仍由 OPS 可执行——这是 F-ADMIN-003「运营可处置 / 驳回」的原文；它复用领域服务，不等于开放处置台。处置台按钮、巡查行内处置按钮对 OPS 隐藏。
  - 最小权限管理：`PUT /api/v1/admin/users/{id}/role`（仅 SUPERADMIN）**只允许 USER → OPS 提升**，幂等、写 `USER_ROLE_UPDATE` 审计；升权后目标用户需重新登录才获得 OPS 权限。
  - dev-only OPS 种子账号 `ops@campuslink.local`（与管理员同门控 `campuslink.roster.bypass=true`），用于联调与验收。
  - 前端 `/admin`：OPS 可进入，仅显示「举报工单 / 内容巡查 / 内容检索」；处置、封禁、看板、标签、角色授予对 OPS 不可见且后端仍拒绝。
- **不做**：
  - **降级 / 撤销 OPS**——现有 JWT 把角色写死在 token 中，撤销后旧 token 仍有效 7 天；须先做 token 吊销 / 会话失效机制（与 F-SAFE-003「封禁即时登出」同一前置），另开 CR。
  - 细粒度权限（按版块 / 按操作）、多角色并存、角色管理列表页 / 用户搜索。
  - 改变举报、处置、封禁、注销的业务语义；不新增迁移、不新增错误码。
  - A3-8、真实名册、W-05。

## 5. 验证

- **单测**：角色层级映射；四个 OPS 端点三态；六个 SUPERADMIN 端点对 OPS 的 403；角色授予的成功 / 幂等 / 目标不存在 / 非法角色 / 改超管拒绝 / 审计；`mvn verify` 全绿（含架构守护 G9，仍走 `requireRole`）。
- **真机**：OPS 账号登录 → 工单 / 巡查 / 内容检索可用，处置按钮不存在；直接 `PUT /admin/posts/{id}/status`、`PUT /admin/users/{id}/status`、`/admin/tags`、`/admin/dashboard` 均 403；SUPERADMIN 全功能回归；匿名 401。
- **契约**：新增 1 operation、4 个描述变更；`git diff` 非空且仅限预期范围。
- **回归面**：既有 SUPERADMIN 调用全部 200；普通用户行为不变；举报 / 处置 / 封禁 / 注销业务语义零变化；前端非管理页零影响。

## 6. 回滚

- 回退提交即可：端点恢复 `ROLE_SUPERADMIN`，OPS 账号立即失去全部管理权限（token 中 `ROLE_OPS` 无端点接受）。
- 角色授予产生的 `users.role` 变更与 `audit_logs` 行保留；如需恢复，按 `USER_ROLE_UPDATE` 审计逐条改回 USER。
- 无迁移、无新依赖；dev OPS 种子账号可随代码回退自然消失。

## 7. 实施结果（实施后追加，不回改上文）

- **与计划一致**：按 §3 全部落地（角色层级、四端点放开、`updateRole` 定向更新、`adminPromoteToOps`、角色端点、dev 种子、前端显隐、契约与文档同步）。
- **实际偏差 1 处**：角色端点的 `@ErrorCodes` **未显式声明 `INVALID_PARAM`**——通用 400 由 `OpenApiErrorResponseCustomizer` 自动补，显式声明会撞出重复 `参数错误（1001）`；非法角色仍返回 `400 / 1001`，由 `AdminUserControllerAuthTest` 与真机证明。
- **验证结果**：`mvn verify` **861 例 / 0 失败 / 14 跳过**；`SPRING_IT=true mvn verify` **861 例 / 0 失败 / 0 跳过**（含 ArchUnit G9、jacoco 80%、SpotBugs、Checkstyle、契约双层比对）；前端 `lint` / `typecheck` exit 0、`build` ✓。
- **真机 API**：OPS 对 contents / review-queue / reports 均 200，对 dashboard / tags / 处置 / 封禁均 **403 / 4002**；匿名 reports **401 / 4001**；SUPERADMIN 五个管理面全 200；角色授予 USER→OPS 200 并记 `USER_ROLE_UPDATE`，重复授予 200 且审计不增，非法角色 400 / 1001，OPS 调用角色端点 403。验收用的 user 2 已用 SQL 回滚为 USER（审计行保留）。
- **真机浏览器**：OPS 登录后 `/admin` 仅 3 个 Tab（举报工单 / 内容检索 / 内容巡查），无数据看板、标签管理、处置按钮、封禁与角色授予；SUPERADMIN 5 个 Tab 且角色授予表单可见；逐 Tab 点击渲染正常，**零控制台错误**。
- **契约**：新增 1 操作 / 1 路径 / 1 schema（`RoleCommand`），4 个既有操作描述改为 OPS / SUPERADMIN；既有 75 操作其余部分零变化。
- **遗留（按范围不做）**：降级 / token 吊销、细粒度权限、角色管理页；OPS 的工单 `REMOVE` 联动处置仍按 F-ADMIN-003 保留。
