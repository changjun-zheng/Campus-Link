## 1. 目标

把 PRD 仅有一行的 F-GAME-001 落成可验证的「等级与声望」：以既有可见贡献（发帖 / 回帖 / 获赞 / 被采纳）计算声望，映射为 6 档社区等级，在本人与他人主页资料卡展示「当前声望 + 等级徽章 + 距下一级进度 + 计分口径说明」。不新建内容形态、不建快照表、不加新端点。

## 2. 范围

**做**

- 新增 domain 纯规则：`ReputationRules`（加权公式）+ `CommunityLevel`（6 档阈值与名称），无框架依赖、可单测；
- forum 侧 `authorStats` 扩为 **4 个计数**：新增回帖数 `replyCount`（与主页回帖时间线同一可见性 WHERE）；
- account 侧主页聚合计算声望 / 等级 / 进度，`GET /api/v1/users/{id}` 出参加字段；
- 前端主页资料卡：昵称旁等级徽章、声望值与升级进度条、计分口径 `el-popover`；统计行补「回帖」；
- 契约快照重抓（`UserProfileVo` schema 变更、0 新操作）、技术方案 §5 / 界面规范 §5.7 / 台账 / 驾驶舱同步。

**不做**

- 帖子列表 / 帖子详情 / 组队页的作者等级徽章（会引入每页 N+1 聚合）；
- 声望排行榜 / 升级通知 / 每日签到 / 徽章收集；
- 新建 `user_reputation` 快照表、定时刷新任务、历史最高声望（**零迁移**）；
- 管理后台展示或改声望、用户自助改名 / 改阈值；
- 匿名发帖（F-FORUM-010）与其它功能。

## 8. 实施结果（实施后追加，不回改上文）

**实施完成（2026-10-25）**，计划 vs 实际如下：

| 项 | 原计划 | 实际 |
|---|---|---|
| domain 规则 | `ReputationRules` + `CommunityLevel`（of / nextThreshold） | 按计划；进度百分比也放进 `CommunityLevel.progressPercent`（纯规则、可单测，避免把边界算在应用层） |
| forum 计数 | `replyCount` 端口 / SQL / `authorStats` 增第 4 数 | 按计划；端口名 `countVisibleByAuthor`，SQL 的 WHERE 与 `findPublicPageByAuthor` 逐字相同 |
| account 聚合 | 4 计数 → 声望 / 等级 / 进度 | 按计划；`PublicProfile` 字段顺序按「四计数 → 等级组 → 关系计数」排列，`nextLevelAt` 为可空 `Long` |
| 契约 | `UserProfileVo` +6、0 新操作 | 实测 **+23 / −0**、69 操作 / 59 路径 / 119 schema / 19 tag / 54 受保护不变、214023 字节；契约 README 升 v1.37 |
| 单测 | 基线 679 → 约 690~700 | 实际 **702 / 0 failures / Skipped 0**（+23 例：`CommunityLevelTest` 17 / `ReputationRulesTest` 4 / `UserProfileApplicationServiceTest` +2），SpotBugs 0 |
| 真机对齐 | 选有发帖 / 回帖 / 获赞 / 采纳的账号手算 | 用 3 个账号交叉验证：id 1（14 帖 / 13 回帖 / 5 赞 / 0 采纳 → 37 声望 / Lv1 / 74%）、id 25（0 / 4 / 1 / 1 → 16 / Lv1 / 32%）、id 32（7 / 5 / 0 / 0 → 12 / Lv1 / 24%），出参与 SQL 逐项一致 |
| 浏览器验收 | 本人与他人主页 + popover | 管理员本人 `/u/1` 与「小A」`/u/25` 均出现徽章 / 声望 / 进度 / 口径 popover；`/u/25` 回帖数 4 与时间线 total 4 一致；控制台仅 SSE 与 Vite 重连的 `net::ERR_ABORTED`，无产品错误 |
| 测试估算偏差 | 690~700 | 702：除计划内的 domain 用例，另给 `UserProfileApplicationServiceTest` 补了「满级 `nextLevelAt=null`」与「声望 / 档位 / 进度同源」两例 |

**偏差与说明**：① 计划里「满级无 `nextLevelAt`」在 `PublicProfile` / `UserProfileVo` 用 `Long` 可空实现，
`non_null` 序列化下满级响应**整个键不出现**（与既有可空字段同形，不是缺字段）；② 未新增任何迁移、端点、错误码与依赖；
③ 验证均在本机原生 MySQL / Redis + 8088 / 5173 上完成，测后未新增任何持久化数据（本 CR 零写路径）。
