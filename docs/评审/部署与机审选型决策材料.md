## 0. 效力边界（先读）

1. **本文是备料，不是评审**：比照 [v0.3/v0.4 追认纪要](技术方案追认纪要.md) 为 A3-2 备料的先例，本文为 A3-8 准备决策输入；**发起人在 §3 勾选之前，A3-8 保持开放**，勾选后须另行登记 CR（结论写入 ADR-011 与技术方案 §8）方可闭环。
2. **建议 ≠ 决定**：本文在两个决策点各给出建议（部署建议方案 A、机审建议阿里云），建议均附理由与反对理由，**均可以被否决**——签署页保留"暂缓"选项。
3. **价格一律不落具体数字**：云主机与机审单价随官方报价变动，本文只给**量级与估算口径**，实际预算以发起人按官网实时报价填写为准（材料中留有填写位）。

## 1. 决策点一：部署形态（ADR-011）

**候选方案（技术方案 §8 原文的两选项，本文不改写其表述）**

| 方案 | 优点 | 代价 | 适用前提 |
|------|------|------|---------|
| A：公网云主机 + 域名 + ICP 备案 | 校外可访问，体验完整，宿舍 / 家里 / 实习地均可使用 | 需 ICP 备案（**1~3 周**，个人主体可办）+ 云主机**数百元 / 月**（量级，以报价为准）；须有内容审核机制 | 目标用户主要在校外访问 |
| B：校园内网服务器 | 无备案与云成本，合规压力小 | **仅限校园网内访问**，宿舍与校外访问受限，对学习论坛体验影响大 | 用户访问集中在校园网 |

**建议：方案 A（公网云主机 + ICP 备案）**

- **支持理由**：
  ① 产品定位是"学习交流论坛"，使用场景天然覆盖**宿舍（运营商宽带）与假期 / 实习地的校外访问**——PRD §5.2 试点策略（邀请制内测 → 面向全校）也以内测社区逐步扩大为路径，内网方案在第二步就失效；
  ② ICP 备案是**排期风险而非技术风险**：1~3 周窗口可在 Sprint 3 开发期间**并行启动**，不占用任何开发工时，但**拖到阶段六启动才办会直接顶住上线日期**——这是本文建议尽早决策的核心动因；
  ③ 成本量级（云主机数百元 / 月）对试点期单人项目可控，且与技术方案 §8"与形态无关的固定项"完全兼容（Docker Compose 编排、GitHub Actions CI、Flyway 迁移、dev→staging→prod 三环境均不随形态改变）。
- **反对理由（如实列出）**：
  ① 引入 ICP 备案与"内容审核机制"两项合规义务——后者本就是 PRD P0（F-SAFE-001 机审 + F-SAFE-002 举报 + F-SAFE-003 处置），非新增负担；前者需发起人以个人主体办理并维护；
  ② 若试点实测发现用户访问确实 95% 以上集中在校园网，方案 B 的零成本优势会重新变得显著——**这是"暂缓"选项存在的意义**。
- **若选 A 须立即启动的事**（供参考，非本文决定）：域名注册与购买 → ICP 备案提交（个人主体，材料以管局要求为准）→ 云主机选型与预算确认。

> **搜索引擎（CR-181）**：部署期可选增一个本机 MeiliSearch 进程（与 backend 同机、仅监听 `127.0.0.1`），以 `SEARCH_ENGINE=meilisearch` 启用；不启用时缺省 MySQL 搜索、部署形态不变。生产必须注入 `MEILI_API_KEY`（`ProductionSafetyGuard` 强制）。

**发起人预算填写位**：云主机预算 ______ 元/月（按官网报价填写）。

## 2. 决策点二：机审服务商选型（F-SAFE-001 实施前置）

**候选（技术方案 §3 选型表原文两选项）**

| 维度 | 阿里云内容安全 | 腾讯云天御 |
|------|--------------|-----------|
| 产品定位 | 文本审核 API 成熟、按量计费（§3 原文） | 同类文本审核 API，微信生态内容治理经验 |
| 接入方式 | REST API 同步调用，发布链路内调用（发帖 / 回复前） | 同左 |
| 计费口径 | 按调用量计费，**以官网实时报价为准** | 同左 |
| 已有技术栈关联 | 无锁定——两家均为纯 HTTP API，切换成本低 | 同左 |

**两家的关键差异点其实在"价格与试用额度"，而非技术**：接入形态同构（同步 REST、返回风险等级标签），技术方案 §5 对机审的唯一硬约束两家都满足——

- **同步调用 P95 ≤ 800ms**（PRD §4 发布类接口指标含机审调用）：须选两家均支持的**同步审核接口**并在实施时压测确认耗时；
- **fail-closed 降级**（技术方案 §7.3）：机审服务异常时按开关关闭发布入口，不可 fail-open——该约定与厂商无关，实施时落在配置开关上；
- **审核结果不留专表**：处置留痕走 `audit_logs`（A3-7 确认口径），风险记录以厂商回执 + 审计日志承载。

**试点期调用量估算（口径如实、供预算用）**：PRD §4 基线为日活 ≥ 1000、单帖回复 ≥ 1000 楼；按发帖 / 回复渗透率估**日审调用数百至数千次量级**，月调用 **1~10 万次量级**——乘以所选厂商官网单价即月预算。两家均对新用户**提供免费试用额度（额度以官网为准）**，试点期实际支出可能为零或极低。

**建议：阿里云内容安全**

- **支持理由**：与技术方案 §3 既有建议一致（文本审核 API 成熟、按量计费）；文档与 SDK 资料丰富，单人项目实施摩擦小。
- **反对理由（如实列出）**：技术层面两家同构、切换成本低，**若腾讯云报价或试用额度更优，没有任何技术理由阻止选腾讯云**——本项目无阿里云生态锁定；因此本决策点实际是**比价决策**，建议发起人决策前花 10 分钟查两家实时单价再勾选。

**发起人预算填写位**：机审月预算 ______ 元（调用量 × 官网单价，按官网实时报价填写）。
