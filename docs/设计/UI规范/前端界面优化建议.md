## 1. 优化结论与边界

**优先做首页信息减量与列表可读性，再做详情阅读与发布编辑体验。** 保留现有蓝白配色、系统字体、Tabler 图标和设计令牌体系，通过更清楚的内容层级形成校园技术社区的辨识度。

本文面向项目发起人与后续开发会话，回答“先改哪里、具体怎样改、怎样证明有效”。本次交付仅为文档；下列批次、尺寸和验收目标均为建议，未经选择不纳入排期，也不代表相关优化已实施。项目进度只看[台账 §1](../../变更日志/变更台账.md)与[驾驶舱](../../进度驾驶舱.html)。

实施边界：

- 复用现有前端栈和组件，不引入新 UI 框架、编辑器、字体、插画或动效依赖。
- 颜色、字号、间距及断点相关规则归入现有令牌与界面规范；正文新增字号应设专用令牌，避免全站正文、按钮及表单一起变大。
- Markdown 继续由服务端统一渲染和净化，前端只消费结果并高亮代码；优化预览布局不改变这条安全边界。
- 注册范围、匿名访问权限、接口契约、数据库和搜索能力不在本次界面建议中变更。文案发现矛盾时先核准产品口径。
- 深色模式、装饰性渐变、外投影和更换品牌配色不列入优先批次；现行素材禁区继续适用。

## 2. 评估依据与限制

评估日期为 2026-11-01。浏览器实际查看了本机 `http://localhost:5173` 的首页、帖子详情 `/post/41` 与登录页；发布页、目录及令牌通过源码核对。**本次没有进行移动端实测、登录后的发布链路验收、读屏测试或新一轮性能测量，也未归档截图文件。** 下表是观察依据，后续批次须重新取证。

| 编号 | 已核实的现象 | 依据 | 判断 |
|------|-------------|------|------|
| O-01 | 首页顶栏和左栏都展示六个版块，右栏包含热榜、等你来答、最新发布 | 首页浏览器画面；[App.vue](../../../frontend/src/App.vue)、[HomeView.vue](../../../frontend/src/views/HomeView.vue) | 导航重复；最新发布与主信息流功能重叠，右栏可减量 |
| O-02 | 列表标题和摘要都单行截断；每条记录同时展示作者、时间、版块、计数与标签 | 首页浏览器画面；[PostListItem.vue](../../../frontend/src/components/PostListItem.vue) 的 `truncate` 与元信息行 | 长问题标题可能丢失关键条件，辅助信息可适度降权 |
| O-03 | 桌面首页中栏与右栏各自滚动，窄屏代码路径改为整页滚动 | 首页滚动条；`HomeView.vue` 固定高度与滚动事件 | 属交互取舍，不能直接判为缺陷；需比较找帖、返回与触底加载体验 |
| O-04 | 所查看的详情帖没有正文标题目录，右侧仍预留空间 | 详情浏览器画面；[PostDetailView.vue](../../../frontend/src/views/PostDetailView.vue) 中目录 `aside` 及其 224px 宽度；[TableOfContents.vue](../../../frontend/src/components/TableOfContents.vue) | 目录内容为空与目录栏占位应一起处理 |
| O-05 | 发布页编辑与预览同处 `max-w-reading` 容器，桌面各占一半；阅读宽度令牌为 760px | [PublishView.vue](../../../frontend/src/views/PublishView.vue)、[tokens.css](../../../frontend/src/styles/tokens.css) | 双栏工作区偏窄，实际净宽还受内边距与栏间距影响 |
| O-06 | 发布页说明包含 `ADR-005`、服务端渲染和安全净化等实现术语 | `PublishView.vue` 页尾文案 | 改为用户可理解的预览与发布说明 |
| O-07 | 登录页写“仅本校同学可见”，本机匿名状态可浏览首页与帖子详情 | 登录页和匿名浏览结果；[LoginView.vue](../../../frontend/src/views/LoginView.vue) | 文案与所观察行为不一致，须对照 PRD 核准；不由本文决定访问权限 |
| O-08 | 首页样本包含大量 CR 编号、取证标题与重复演示内容 | 首页浏览器画面 | 当前内容不足以代表真实社区，需合成样例校准设计 |

已存在的能力应保留：草稿自动保存与恢复、服务端实时预览、代码高亮与复制、正文目录、已采纳标识、键盘焦点反馈及加载失败重试。它们不是本文提出的新功能。

## 3. 优化清单

下表中的“高／中”为本文内部建议顺序，不对应 PRD 的 P0／P1 需求等级。

| 编号 | 优化项 | 优先级 | 预期收益 | 主要落点 |
|------|--------|:------:|----------|----------|
| UI-01 | 首页导航与右栏减量 | 高 | 主信息流更突出，减少重复入口与内容 | `App.vue`、`HomeView.vue` |
| UI-02 | 帖子列表阅读层级 | 高 | 保留问题关键条件，提升扫读效率 | `PostListItem.vue` |
| UI-03 | 首页滚动与返回体验 | 中 | 列表位置稳定，降低多滚动区的理解成本 | `HomeView.vue`、路由相关逻辑（按需） |
| UI-04 | 详情阅读与目录占位 | 高 | 长文易读，空目录不占位 | `PostDetailView.vue`、`TableOfContents.vue`、`tokens.css` |
| UI-05 | 发布编辑工作区 | 高 | 编辑、预览与保存反馈更清楚 | `PublishView.vue`、`tokens.css` |
| UI-06 | 移动端关键操作 | 中 | 搜索、发帖、回帖在窄屏与软键盘下可用 | `App.vue`、首页／列表／详情／发布视图 |
| UI-07 | 登录与发布文案 | 高 | 文案准确，用户知道下一步与可见范围 | `LoginView.vue`、`PublishView.vue` |
| UI-08 | 合成内容样例集 | 高（验收准备） | 用真实长度与结构检验布局 | 验收文档；需要入库时另按数据脚本约定处理 |

### UI-01：首页导航与右栏减量

- 推荐桌面端由左栏承载六个版块，顶栏保留品牌、搜索、提问、组队及账号操作。进入没有左栏的页面时仍须提供可见的版块切换入口，不能直接全站删掉顶栏版块导航。
- 右栏以“等你来答”为首，“全站热榜”为次；“最新发布”从首页右栏移除，主区“最新”已承载该用途。“关于”保留简短定位。
- 保留现有总容器宽度，优先把减少的导航和辅助内容转化为更宽的主信息流；具体栏宽用长标题样例与断点验收确定。
- 热榜“更多”应进入与热榜语义一致的列表；当前链接指向 `/board/qna`，实施时须核对目的页排序与范围，不能把普通问答列表当作全站热榜。

### UI-02：帖子列表阅读层级

- 标题最多两行，摘要最多一行；标题保持第一视觉层级。完整标题应能通过可访问名称和进入详情读取，不能只依赖鼠标悬停。
- 作者、时间保留为次级信息；阅读、点赞、回复计数使用统一对齐与格式，降低视觉权重，保留现有就地点赞。
- “已采纳”延续现有语义；“待解答”若新增，须明确依据帖子类型与采纳状态，不能仅以回复数为零推断，也不能混淆“未采纳”与“零回答”。
- 标签最多展示少量，长标签截断但保留可理解名称；带图与无图记录的标题、摘要和元信息保持一致节奏。
- 共享组件同时回归首页、版块、搜索与收藏，保留搜索命中高亮、匿名作者展示及点赞状态。

### UI-03：首页滚动与返回体验

- 保留现状与整页滚动作为两个比较方案，先用同一组内容完成“滚动找帖 → 进入详情 → 返回 → 切换排序”任务。
- 优先确保返回后排序、已加载数据与滚动位置保持；切换“最新／热门／关注”后定位到新列表起点。
- 若选择整页滚动，左右栏可在空间允许时吸顶；若保留独立滚动，中栏必须支持键盘滚动、清楚的滚动提示及独立回顶。
- 两种方案都需证明首屏不会自动拉完全部分页、触底能续载、失败能重试、重复触发不重复追加。

### UI-04：详情阅读与目录占位

- 建议正文试用 16px、约 1.8 行高，阅读内容最大宽度沿用约 760px；标题、列表和表单使用各自层级，不全站放大字号。
- 只有存在可用目录条目时才保留目录侧栏；无目录时移除侧栏占位并居中正文。有目录时仍支持锚点定位与当前章节提示。
- 帖子标题、作者信息、正文、互动区、回复区形成清楚的纵向顺序；点赞、收藏、回复为主要操作，举报降低视觉权重但保持可达。
- 保留最佳答案强调与楼层语义；长代码横向滚动应限制在代码块内，不能撑宽整页。复制按钮继续使用现有能力。

### UI-05：发布编辑工作区

- 桌面编辑工作区建议试用 1040～1120px 上限；在空间足够时双栏，窄于适用宽度时切换编辑／预览。编辑器工作宽度与正文阅读宽度分开管理。
- 使用可收缩的等分列和明确间距，避免“两列各 50% 再加间距”导致溢出；标题、版块与发布操作保持稳定对齐。
- 基于现有保存逻辑显示“草稿已保存／保存失败”等准确反馈；编辑已有帖子时不显示新帖草稿保存状态，避免误导。
- 发布／保存修改按钮明确区分，提交中防止重复点击，失败保留正文；恢复草稿后应能继续编辑并正确发布。
- 页尾文案建议改为“支持 Markdown，预览效果与发布后一致。请遵守社区规范。”技术依据保留在开发文档中。

### UI-06：移动端关键操作

- 先保证搜索、版块切换、发帖、回帖可以直接找到；是否增加底部固定导航应在实测后决定，不默认增加一套重复导航。
- 主要触控操作建议达到 44×44 CSS px，图标可保持原尺寸，通过容器扩大命中区；状态不能只用颜色区分。
- 长标题、长昵称与多个标签不得挤出操作区。移动端保留已采纳状态、回复数等必要信息，辅助统计可收起。
- 实机确认软键盘弹出后输入区、校验提示与提交按钮可见或可滚动到达；验证底部安全区、横屏与浏览器返回行为。

### UI-07：登录与发布文案

- 先对照 PRD 核准“注册资格”与“内容可见范围”。若允许匿名阅读，可采用“面向本校学生，注册需学籍核验”；若要求内容仅本校可见，则另开需求／鉴权变更，不能只靠改文案处理。
- 登录、注册及校验提示使用一致的“邮箱／手机号”“验证码”称呼；按钮描述实际动作，保留注册两步流程与失败统一提示。
- 删除用户界面中的架构编号与内部实现术语；保留验证码时效、失败恢复等能帮助用户决策的信息。

### UI-08：合成内容样例集

准备不少于 12 条合成帖子，覆盖六个版块，包含长短标题、零回复／多回复、已采纳／未采纳、代码块、图片、有无标签、长昵称与匿名作者。示例主题可用“Java 集合遍历时报 ConcurrentModificationException”“数据库课程实验分组”“程序设计竞赛寻找前端队友”。不得使用真实学号、手机号或私人信息。

样例先写成验收用例；需要入库时按数据脚本规则默认 dry-run，并明确数据标识与清理方案。本文不授权写入、覆盖或删除已有测试数据。

## 5. 验收标准与取证

### 5.1 视觉与操作验收

| 验收项 | 建议通过条件 |
|--------|-------------|
| 断点 | 375、768、1024、1280、1440 CSS px；无页面横向溢出、页头重叠、导航裁切或主要操作遮挡 |
| 首页 | 从可见入口进入六个版块、搜索和发布；右栏不重复展示“最新发布”；热榜入口与结果语义一致 |
| 列表 | 长标题最多两行，标签和计数不覆盖；首页／版块／搜索／收藏表现一致；搜索高亮与点赞反馈保留 |
| 滚动 | 首屏、触底续载、失败重试、回顶、详情返回与排序切换逐项验证，记录加载页数及返回位置 |
| 详情 | 有／无目录各测一帖；无目录无侧栏空占位，有目录能定位；长代码不撑宽页面，复制及已采纳展示正常 |
| 发布 | 进入 → 预填 → 编辑 → 预览 → 草稿恢复 → 发布／保存 → 回跳详情；标题、正文与标签结果一致 |
| 结果可查 | 修改标题／标签后搜索新值命中、旧值不再命中；纯排版批次按实际影响缩减，不虚报完整发布验收 |
| 移动端 | 实机软键盘下能完成编辑、校验与提交，主要操作可触达；设备与浏览器写入验收记录 |
| 无障碍 | 键盘完整操作、可见焦点、清楚的控件名称；修改过的表单补查错误关联与焦点回还，状态不只依赖颜色 |

### 5.2 工程与性能验证

- 代码实施后运行 `npm run build`、`npm run typecheck`、`npm run lint`；纯文档交付运行 `python backend/scripts/check_docs_consistency.py`。
- 样式与布局不应新增运行时依赖。共享样式修改后检查 Element Plus 的 CSS 变量覆写与 Tailwind 层叠边界，避免局部正常、其他页面失效。
- 对本批受影响页面，用[性能基线](../../开发/性能基线实测-2026-10-26.md)的同条件采样比较；记录 LCP、TBT、CLS 与加载字节。建议关注 LCP <2.5s、TBT <200ms、CLS <0.1，未达到时写明实测值与原因，不能以 Lighthouse 总分替代。
- 同条件冷缓存至少三次取中位数；若显著退化或出现布局跳动，先归因再扩大批次。前端渲染等待与后端检索延迟分开记录，界面优化不能宣称解决搜索容量问题。

### 5.3 证据归档格式

各实施批次在对应验收文档记录：CR、代码范围、环境／设备／视口、样例 ID、操作步骤、预期、实际、截图路径、验证命令结果及未覆盖项。前后截图使用同一内容、同一视口、同一登录态；记录加载／空态／失败态，不能只截正常首屏。

截图和实际结果在实施时生成。完成情况与新问题登记在台账和驾驶舱，本文保留为建议依据，不追加会话进度流水。

## 6. 选择与决策清单

实施前由发起人选择首批范围，并确定三项会影响页面结构的取舍：

1. 首页版块导航的集中位置，以及没有侧栏页面的切换方式。
2. 首页保留独立滚动还是改为整页滚动；按 UI-03 的任务实测后选择。
3. “仅本校同学可见”的产品口径；先核准资格与可见范围，再决定文案或另立需求。

推荐从批次 A 开始。本文尺寸是试验起点，最终值以真实内容、浏览器验收及更新后的界面规范为准。
