## 0. 使用须知（先读这一节）

本文是**候选池与判定表**，不是待办清单，也不是采购单。三条铁律：

1. **已采用的不重复选** —— §1 是事实基线。选型前先看 §1，不要推荐项目已经在用的东西；
2. **被规范禁用的不因本文解禁** —— §3 的禁区逐条带依据条文。想用必须先改规范（另开 CR 动 [界面规范](./界面规范.md)），**不能由本文开先例**；
3. **新增素材 = 新增依赖或新增规范例外** —— 命中 [CR-034](../../变更日志/变更台账.md) 实施方案门槛，须**先开 CR、写方案、停下等确认**，再动代码。本文**不授权任何落地**。

## 5. 新增素材的标准动作

1. **查 §1**：项目是否已有同类？有就别加（混用比没有更糟）；
2. **查 §3**：是否撞禁区？撞了就先改 [界面规范](./界面规范.md)，别先写代码；
3. **判断是否新增依赖**（`package.json`）：是则命中 [CR-034](../../变更日志/变更台账.md) 门槛；
4. **开 CR**（[变更台账](../../变更日志/变更台账.md) §1 一行式登记）→ 写实施方案 `docs/开发/实施方案/CR-xxx-主题.md`（一页以内六节）→ **停下等确认**；
5. **落地后同步**：动了 UI 规则 → [界面规范](./界面规范.md) 加注；动了接口 → `openapi.json` 重生成；收尾按 [AGENTS.md](../../../AGENTS.md)「工作收尾约定」更新驾驶舱。
