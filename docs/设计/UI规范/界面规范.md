## 0. 本文是什么、不是什么

**是**——

1. **[W-03](../../流程偏离记录.md) 补偿①的落点**：把"组件与交互规范约定"写成可查的文件。[docs/README.md](../../README.md) §4 第 3 条要求在执行补偿②时"顺带写下补偿①的组件与交互规范约定"，本文即该产物；
2. **[W-03](../../流程偏离记录.md) 补偿②的归档容器**：建立 `./`（此前**不存在**），登记已跑通页面清单与截图位（见 §8）。

**不是**——

- **不是被 W-03 砍掉的交互稿 / 视觉稿**。W-03 的裁剪结论继续有效：本项目**不产出**交互稿与视觉稿，路线是"按 [PRD](../../需求/产品需求文档.md) §5.1 页面清单直接用 Element Plus 拼装"。本文只写**约定与清单**，不含高保真稿、不含组件视觉设计；
- **不是新的技术决策**。本文不改变 [ADR-002](../技术方案.md)（前端栈）、[ADR-005](../技术方案.md)（Markdown 服务端渲染）与 [ADR-011](../技术方案.md)（部署形态）的任何结论；
- **不构成改代码授权**。§3 的不一致清单与 §4 的令牌建议若要落地（新增 `tokens.css`、改组件样式、补依赖），按"**先登记后实施**"须另开 [CR](../../变更日志/变更台账.md)——比照 A3-10 的处置口径。

> **边界自述**：本文是**据实描写**，不是"设计已评审通过"的证据。W-03 三条补偿措施中只有本条（目录 + 清单）可推进，**补偿③（提测前逐页走查）仍未执行**，设计门出口标准第 3 项**仍为 ❌**。

## 2. 设计定位（信息架构原则）

**产品形态**：Web 网站优先（桌面 + 响应式），**内容型垂直社区**，单校范围（[技术方案](../技术方案.md) 第 1 节）。

由此确定的**三条硬约束**：

1. **信息密度优先，列表页是主战场**。用户 80% 的时间在扫列表，判定列表页好坏的标准是"一屏能扫几条、每条能否看清是否值得点"，不是视觉张力；
2. **内容为主体，装饰为零**。不做插画、不做渐变、不做大圆角卡片堆叠——这些会挤掉列表的信息密度；

> **v1.7 定点放宽（[CR-052](../../变更日志/变更台账.md)，发起人选定"适度品牌化"）**：本条文**继续成立**，仅存在 **4 处定点、可枚举的偏离**（见头部 v1.7 性质说明）：hero 唯一渐变、6 版块识别色仅用于图标容器、版块卡 hover 微抬但无外投影、毛玻璃仅 sticky 顶栏。**除此之外任何渐变 / 插画 / 投影 / 大圆角 / 彩色小号文字仍按本条文禁止**；4 处之外想再放宽，须另开 CR 并在此表登记。
3. **导航服从"版块少、层级浅"**。当前 6 个固定版块（`qna` / `resources` / `interview` / `contest` / `course` / `chat`，见 [PRD](../../需求/产品需求文档.md) F-FORUM-001）。

### 4.1 落地方式

**新增 `frontend/src/styles/tokens.css`，在 `main.ts` 中一次性引入**（纯 CSS 自定义属性，**不引入任何构建依赖**）。

> **加注偏离（v1.1，[CR-023](../../变更日志/变更台账.md)，2026-09-12）——本条已被推翻，原文保留**：落地方式按本条执行（`tokens.css` + `main.ts` 一次性引入），**但"不引入任何构建依赖"这条限制被 [CR-023](../../变更日志/变更台账.md) 推翻**——同时引入了 `tailwindcss` + `@tailwindcss/vite` 两个 devDependencies 作为**样式工具层**（Element Plus 仍是唯一组件库，未换栈）。**后果（已在 CR-023 登记为最大技术风险）**：Tailwind v4 产出**分层**样式（`@layer`），而 EP 样式**未分层**，**未分层样式恒胜分层样式**，故**工具类无法覆写 EP 组件内部样式**。由此形成的边界约定：**EP 组件一律走 CSS 变量（在 `tokens.css` 用 `:root:root` 覆写），自有元素才用工具类**；该边界**无 lint / 测试强制**，靠 `AGENTS.md` 的人工约定。

**与 Element Plus 的关系**：不另起一套平行体系。Element Plus 已用 `--el-*` 定义主色、圆角基数等，**已有的一律复用，只补它没有的**（间距刻度、阅读列宽、元信息文本色、分隔线色）。必要时以映射方式覆写，例如 `--el-text-color-regular: var(--cl-text-regular)`。

> **加注（v1.1，[CR-023](../../变更日志/变更台账.md)）——本条被完整执行且加强了**："不另起平行体系"已落实；覆写不止于"必要时映射"，而是**成批覆写**（主色与 `light-3/5/7/8/9`、`dark-2`、六档字号、`--el-border-width` 等），全部集中在 `tokens.css` 一处。**一处刻意的例外**：`--el-box-shadow-light` **不覆写**——下拉菜单 / 消息提示等浮层仍需阴影表达层级（去阴影只针对卡片，经模板 `shadow="never"` 归零）。

### 5.5 时间显示

- 传输：ISO-8601 UTC；展示：前端本地化（`utils/time.ts` 的 `formatTime`，输出 `YYYY-MM-DD HH:mm`）；
- **建议（P1）**：列表页改用**相对时间**（`3 小时前` / `昨天`），详情页保留绝对时间。列表页的绝对时间对扫读帮助有限，而"多久之前"直接回答"这条热不热"。

> **v1.3 状态更新（[CR-025](../../变更日志/变更台账.md)）——本建议已落地（P1 → ✅）**：`utils/time.ts` 新增 `formatRelativeTime`（**刚刚 / N 分钟前 / N 小时前 / 昨天 / 前天 / N 天前，超过 7 天回退绝对时间**），**首页 / 版块列表的帖子时间改用它，详情页与楼层保留 `formatTime` 绝对时间**——分工与上条建议完全一致。**一处随设计稿的呈现细节**：列表元信息各段之间用「·」分隔（作者 · 回复数 · 相对时间）。
>
> **v1.6 加注（[CR-048](../../变更日志/变更台账.md) / [CR-049](../../变更日志/变更台账.md) / [CR-050](../../变更日志/变更台账.md)）——两件事，一为据实补齐、一为如实记缺陷**：
> ① **上条"首页 / 版块列表"的枚举已过时**：`/favorites`、`/search`、`/notifications` 三个后建页面的时间位**同样调用 `formatRelativeTime`**（逐行读 `views/*.vue` 的 import 核实），**详情页正文与楼层仍用 `formatTime` 绝对时间**——分工约定未被破坏，只是覆盖面扩大。
> ② **⚠️ 相对时间口径会把时间戳偏移缺陷放大成用户可见的错误**（缺陷本体见[接口契约 §4.7](../接口契约/README.md) 的时间警示，登记为 **CR-051 候选**，**本次未修**）：后端 `created_at` 以本地墙钟写入、按 UTC 读出，下发的 `...Z` 值比真实 UTC **快 8 小时**，`formatRelativeTime` 里 `Date.now() - date` 因此**恒偏小 8 小时**。**后果已按 `utils/time.ts` 的分支逐一算过**：真实距今 **8 小时以内**的通知全部落进 `diff < 60_000` 分支，**一律显示"刚刚"**（0.5h / 2h / 7h 三档实测输出同为"刚刚"）；20 小时前的显示"12 小时前"、100 小时前（约 4 天）显示"3 天前"，**跨天档位整体前移约一天**。**凡调用 `formatRelativeTime` 的页面同等受影响**（首页 / 版块 / 收藏 / 搜索 / 通知五处），只是通知中心的**全部价值就是"什么时候发生的"**，这里最先被当成缺陷发现。修法在源头（写 UTC 或改 JDBC 时区口径），**不在前端做 -8h 补偿**（那是把错误搬到第二层）。

### 5.6 Markdown 正文与代码高亮

**这是 ADR-005 的硬边界，前端不得越界**：

| 项 | 约定 |
|---|---|
| 渲染位置 | **只在服务端一个执行点**（`common/markdown`）。发布时渲染 `content_html` 落库，请求时**零渲染** |
| XSS 防线 | 在服务端的 `MarkdownRenderer`（flexmark + jsoup 白名单），**不在前端**。前端只负责 `v-html` 呈现 |
| **禁止** | 前端二次渲染 Markdown 做正文展示；前端自行拼接 HTML |
| 代码高亮 | **由前端 `highlight.js` 完成**（服务端只输出 `<pre><code class="language-*">`，避免为 hljs 的样式类扩大白名单）——**当前未实现，属欠账** |
| 样式归属 | `.markdown-body` 必须**提为全局样式**（现状写在 `PostDetailView.vue` 的 `scoped` 中，**发帖预览无法复用**） |

> 代码块样式最低要求：`background: var(--cl-bg-code)`、`--cl-radius-sm`、`overflow-x: auto`、行内 `code` 用等宽字体；**长代码必须横向滚动而非换行**。
>
> **v1.1 更新（[CR-023](../../变更日志/变更台账.md)）**：**"样式归属"一行已落地**——`.markdown-body` 已从 `PostDetailView.vue` 的 `scoped` 提为**全局内容排版**（消费令牌，供后续发帖预览复用），手写字号 / 颜色改为消费 `--cl-*`；**代码块样式最低要求已在真实帖子中逐项实测通过**（背景、圆角、`overflow-x: auto`、等宽行内 `code`）；**文字链接改用主色 `#0f766e`**（不再是 `#409eff`）。**仍未做**：**`highlight.js` 依然没有引入**——服务端输出的 `class="language-*"` 目前没有任何前端着色，**ADR-005 的欠账未兑现**（§3 第 8 项、§9.1 P0 第 4 项仍开放）。
>
> **v1.8 状态回填（[CR-055](../../变更日志/变更台账.md) 批次①，上表四行原文一字未改）**：⚠️ **本条上文与上表均保留不改写**，因为它们记录的正是当时的真实状态；据实更正如下——**"代码高亮"行末尾的"当前未实现，属欠账"已过期**：`highlight.js` `^11.12.0` 已引入（依赖、`src/utils/highlight.ts`、`src/styles/hljs.css`，随 `286739b` 提交），**该行的约定按原文实现、未打任何折扣**：服务端仍只输出 `<pre><code class="language-*">`（**没有为 hljs 的样式类扩大白名单**，后端 `MarkdownRenderer` 与 `MarkdownRendererTest` 的 6 个 XSS 用例零改动），前端 `v-highlight` 指令**只读已渲染 `pre code` 的 `textContent` 着色**，**不二次渲染 Markdown、不自行拼接 HTML、不做前端净化兜底**（本表"禁止"一行仍是被遵守的那一侧）。**"样式归属"一行的两处现状另需注意**：`.markdown-body` 自 v1.1 即已提为全局，但**hljs 的色板不走 `.markdown-body`、而是另立 `src/styles/hljs.css` 的 `.hljs-*` → `--cl-code-*` 令牌映射**（上游主题 CSS 含字面 hex，未引入以守 §4"颜色只来自令牌"；另有三处主动偏离：不设 `background`、不搬 `padding` / `overflow`、`.hljs-section` / `.hljs-strong` 的 `font-weight: 700` **降为 500** 以守 §2 字重只用 400 / 500）。**底部"代码块样式最低要求"一行不受影响**（长代码横向滚动由 `.markdown-body pre` 负责，hljs 不重复声明）。**仍未做**：**着色的像素级目视走查**——本轮只核到依赖 / 源码 / 调用点，实际观感（配色对比度、深浅色块是否与 §4 令牌一致）待发起人在带代码帖的真实页面上判定；**[ADR-005](../技术方案.md) 的这条欠账就此闭环，但"落地"不等于"验收"**。

### 5.7 鉴权与跳转

- 受保护路由（`/publish`、`/notifications`）由路由守卫统一拦截，未登录跳 `/login?redirect=<原路径>`（现状已实现）；
  - **v1.6 据实补齐清单（[CR-048](../../变更日志/变更台账.md) / [CR-050](../../变更日志/变更台账.md)）**：`meta.requiresAuth` 现为 **3 个**路由——`/publish`、`/favorites`（[CR-048](../../变更日志/变更台账.md)，本条原文漏登记）、`/notifications`（[CR-050](../../变更日志/变更台账.md)，此前是占位页、现在是需要登录的真页面）。**守卫逻辑一条未改**，只是被保护的页面变多了；`/search` 与 `/post/:id` 保持公开。
- 页面内触发受保护操作（如发回复）**必须二次判断登录态**并携带回跳，不能只依赖路由守卫——因为详情页本身是公开的；
- **前端显隐只是体验，不是安全边界**：真正的鉴权在后端。**该项事实已于 2026-09-12 更新（[CR-031](../../变更日志/变更台账.md)，v1.4）**：框架级路径拦截已落地——`SecurityConfig` **不再是 `permitAll()`**，改按 `EndpointAuthorizationManager`（以端点注解为单一事实来源）在过滤器链内裁决，匿名在进入业务代码前即被拒（`401 / 4001`）；业务层再由 `CurrentUser`（`requireId` / `requireRole`）承担角色与资源级授权。**前端约束不变**：**不得**因"后端拦了"而省略登录态判断（前端要的是**体验**：未登录跳登录页、操作携带回跳），也不得因"前端拦了"而认为安全。

### 5.7 他人主页 `ProfileView.vue` 的现行约定（v1.11 新增，随 [CR-104](../../变更日志/变更台账.md#cr-104)）

  （CR-102 立的"计数用等宽数字"约定，本页此前漏用，本轮补齐）；计数与"无内容"是两种状态，**空值回 0 而不是省略字段**。
- **两条时间线用自有文字型 Tab（帖子 / 回帖）**，样式沿用首页 CR-091 那一套：主色文字 + 底部 0.5px 指示条、

  回帖档的 `replies / repliesTotal / replyPage / repliesFetched / activeTab` 也必须在 `loadAll` 里复位，
  否则上一个人的楼层会停在下一个人的页面上；异步响应继续走 `reqSeq` 序号守卫（不是最新一轮的一律丢弃，含 catch 分支）。

  但**没有「已下架」标签**——后端 `PublicReplyVo` 出参就没有 `status` 位，被处置的楼层在 SQL 侧已整条滤掉。
  ⚠️ 这不是样式差异，是**权限口径**：公开页不得下发处置事实。
- **「粉丝 / 关注」两个计数是链接（[CR-130](../../变更日志/变更台账.md#cr-130)）**：点入 `/u/:id/followers` / `/u/:id/following`，
  两条路由复用同一 `FollowListView.vue`（文字型双 Tab 切换，样式沿用上一条 Tab 约定）；列表条目 = 头像 + 昵称 + `专业 · 签名`，
  **条目内不放关注按钮**（关注在主页完成，避免逐条携带 viewer 关系与 N+1 请求）；两条路由 `requiresAuth`——
  匿名点击计数由路由守卫跳登录并带回跳。⚠️ 列表页脚注必须如实写「已注销账号与已被你拉黑的账号不在此列出」：
  接口 `total` 是**可点开的条目数**，与资料卡「粉丝 / 关注」数字（关系事实数）**可能不同，两处不得互相替代**。

- **边界**：只消费既有令牌与既有图标（`pencil` / `eye`），**不引入新图标 / 新组件库 / 新渐变**；列表项整行是 `RouterLink`，不做行内按钮嵌套。
