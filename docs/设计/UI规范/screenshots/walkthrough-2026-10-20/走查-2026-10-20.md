## 2. 环境与方法

- **真实栈**：MySQL 3306 / Redis 6379 / 后端 8088 / 前端 dev server 5173，开发库数据，单机单内核；
- **采集方式**：隔离无头 **Edge 155**（独立 `--user-data-dir`）+ **CDP**（Node 内置 `WebSocket`，零新依赖），
  `Emulation.setDeviceMetricsOverride` 强制视口（移动 375×812×1 / 桌面 1440×900×1）；
- **登录态**：`POST /auth/captcha` + `POST /auth/login`（`dev-stu-01@dev.campuslink.local` + 固定验证码 `123456`），
  写入 `cl_token` / `cl_user` / `cl_exp` 后导航；后台页用**匿名**探针验证「跳登录且带 redirect」；
- **逐页证据**：正文长度 / 控制台错误数 / 截图字节数，原始数据见同目录 `report-2026-10-20.json`；
- **边界**：程序化采集，**不充抵**补偿② 的人工采集口径（§8.1 第 7/8/9 行的人工口径仍空）；未做像素级比对。

## 4. 本轮发现：BUG-012（顶栏版块导航在桌面端被截断，**未修复、已登记**）

- **现象**：1440 / 1366 / 1280 甚至 **1920** 宽度下，顶栏导航容器恒为 **362px**、内容 **500px** ⇒
  「竞赛交流」被截半、「闲聊灌水」完全在屏外；容器是 `overflow-x-auto` 且**滚动条被隐藏**，用户没有任何"还有更多"的提示；
- **量测**：`header > div` 内层 `max-w-page = 1080px`；logo 145 + 右侧簇 533 + 间距 40 之后导航只剩 362；
- **一次被回滚的修复尝试**：把导航改 `md:flex-none` 后 `scrollWidth == clientWidth`（指标变绿），
  但截图显示**页头折成两行**（导航挤走 logo / 搜索），且首页左右栏的 sticky 偏移是按 60px 顶栏写死的 ⇒ **回滚**。
  这条负结果一并留档：**"宽度指标通过"不等于"布局正确"，收尾必须看图**；
- **为什么不本轮修**：真修要动 `max-w-page`（1080，全局容器）或右簇里搜索框 / 按钮的固定宽度——属全局布局取舍，
  交发起人定（选项：加宽容器 / 右簇在窄档位收缩 / 导航保留横向滚动但补可见提示）。
